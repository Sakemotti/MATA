# MATA 祝日データ連携・再計算仕様

- 文書状態: 初版
- 最終更新日: 2026-08-10

## 1. 適用範囲

- 祝日除外を適用するのは`repeatType = weekdays`だけとする。
- 月曜日から金曜日のうち、祝日キャッシュに存在しない論理日を実行対象とする。
- 土曜日と日曜日はキャッシュ状態にかかわらず対象外とする。
- 他の繰り返し方式、週X回・月X回の有効日数、期間境界は祝日によって変更しない。
- 各利用箇所は[繰り返し計算仕様](../domain-specs/recurrence-rules.md)の共通計算結果を使用する。

## 2. 未取得時の暫定計算

- 必要年の利用可能なキャッシュがない場合、月曜日から金曜日を暫定的な実行日とする。
- 暫定状態でもTODOの登録、編集、完了、スキップを許可する。
- API取得範囲外の将来年も同じ規則で暫定計算する。
- 既存キャッシュがある場合は、通信失敗または更新期限超過時もキャッシュを使用する。
- 長期未起動期間に取得不能な過去年がある場合は、月曜日から金曜日による暫定結果で整合処理を継続する。
- 暫定状態で確定された過去履歴は、後から祝日情報を取得しても変更しない。

## 3. UIへ提供する状態

計算結果には、通常の実行対象情報に加えて次を含める。

- 祝日情報が確定済みか暫定か
- 取得済みだが更新期限を超えているか
- 取得中か
- 最後の取得が失敗したか
- 対象日の祝日名
- プレビューから祝日として除外した日付と名称

状態を色だけで表さず、テキスト、アイコン、セマンティクスを併用する。

## 4. TODO編集画面

- 必要年が未取得の場合は「祝日情報を取得できないため、平日の予定は暫定表示です」と表示する。
- 暫定状態でも、他の入力が有効なら保存できる。
- 平日のみのプレビューでは、直近候補から除外した祝日の日付と名称を表示する。
- 取得中、取得失敗、期限超過を区別して画面モデルへ提供する。
- 取得成功後は入力値を維持したままプレビューを再計算する。
- 祝日取得のために保存操作を待機させない。

## 5. TODO一覧とカレンダー

- 表示対象日の判定が暫定の場合は、画面内に簡潔な暫定状態を表示できるモデルを提供する。
- 更新により現在日の未操作TODOが対象外になった場合は、次回の画面状態更新で行を非表示にする。
- 更新により現在日が実行対象になった場合は、未操作かつ他条件を満たすTODOを表示する。
- 過去の確定済み履歴表示は変更しない。
- 祝日名が変更された場合、現在と将来の説明、プレビュー、カレンダー補足へ新しい名称を反映する。

## 6. ウィジェット表示

- ウィジェット側で祝日判定を再実装しない。
- 共通Repositoryが生成したWidgetDisplayModelを使用する。
- 新たに祝日となった日の未操作の平日のみTODOを非表示にする。
- 新たに実行対象となった平日のみTODOを表示する。
- 長い取得エラー文は表示しない。
- 暫定状態の明示が必要な場合は警告アイコンとアプリを開く操作を提供する。
- 更新失敗時は最後の正常なウィジェットスナップショットを維持する。
- 古いスナップショット上の完了操作では最新の祝日状態とTODO状態を再検証する。

## 7. 祝日更新の変更判定

- 年単位データハッシュが変わった年だけを更新対象とする。
- 追加、削除、日付変更、名称変更を変更として扱う。
- 変更された日付集合と、名称だけが変更された日付集合を導出する。
- 更新世代ID、変更年、変更日付集合を永続化する。
- 同じ更新世代を複数回処理しても結果が重複しないようにする。

## 8. 更新後の再計算

変更年に実行期間が重なる平日のみTODOへ次を適用する。

1. 各カテゴリの終了時刻から現在論理日を決定する。
2. 保存済み実行記録、期間結果、TODO定義を取得する。
3. 未確定の現在分と将来分を新しい祝日集合で再計算する。
4. 一覧、プレビュー、通知、ウィジェットの更新要求を発行する。

- 確定済みの完了、スキップ、未完了履歴を変更しない。
- 確定済みの週・月期間結果を変更しない。
- 履歴スナップショットを書き換えない。
- 現在日に保存済みの完了またはスキップ記録がある場合は維持する。
- 祝日名だけの変更では実行対象を変えず、現在と将来の表示名称だけを更新する。

## 9. 現在日の変化

### 9.1 新たに祝日となった場合

- 未操作の平日のみTODOを現在の一覧とウィジェットから除外する。
- 対象日の将来通知を取り消す。
- 同じ論理日に完了またはスキップ済みなら記録を維持する。
- 論理日終了後の確定済み未完了記録を削除しない。

### 9.2 祝日ではなくなった場合

- 他の有効期間、アーカイブ、繰り返し条件を満たす未操作TODOを表示する。
- まだ経過していない将来通知を登録する。
- すでに経過した通知を発火させない。
- 確定済み履歴が存在する場合は新しい未操作状態を重複生成しない。

## 10. 通知との連携

- 祝日更新後は変更年に関係する平日のみTODOの将来候補を再構築する。
- 新たに対象外となった日のOSアラームを取り消す。
- 新たに対象となった日の未経過通知だけを登録する。
- 経過済み通知を遡って発火させない。
- 通知Receiver内でAPIへ接続しない。
- Receiverは取得済みキャッシュと現在のドメイン状態だけを使用する。
- 古い祝日情報で登録されたアラームも、表示直前に最新状態を再検証する。
- 表示直前に祝日と判定された場合は通知を表示せず、次回候補を再計算する。
- 再構築に失敗した場合は更新世代を未処理のまま保持し、WorkManagerで再試行する。

## 11. 更新世代と後続処理

キャッシュトランザクション成功後に、同じ更新世代で次を管理する。

- ドメイン再計算
- 通知再構築
- ウィジェット更新
- UI状態更新

- 各処理は完了状態を個別に記録する。
- 後続処理の失敗を理由に正常な祝日キャッシュを以前へ戻さない。
- 未完了の処理は次回起動またはWorkManagerで再開する。
- 通知とウィジェットの更新要求は複数回実行しても同じ結果になるよう冪等にする。
- 古い通知は表示前の再検証で抑止する。

## 12. プロセス終了と障害復旧

- 取得試行、キャッシュ更新、後続処理の段階を永続化する。
- キャッシュ更新前の終了では既存キャッシュを維持する。
- Roomトランザクション中の終了ではトランザクションをロールバックする。
- キャッシュ更新後の終了では、未処理の更新世代から後続処理を再開する。
- 復旧処理完了まで新しい同一更新世代を作らない。
- 同じ復旧処理を繰り返しても履歴、通知、ウィジェット状態を重複させない。

## 13. バックアップ復元との連携

- 祝日キャッシュと取得状態はバックアップから復元しない。
- 復元前から端末にある有効なキャッシュは維持する。
- 復元したTODOに必要な取得可能範囲内の年が未取得なら取得Workを登録する。
- 取得までの間は暫定計算を使用する。
- 復元直後に経過済みの通知を発火させない。
- 祝日取得後は復元済みTODOの未確定な現在と将来だけを再計算する。

## 14. エラー分類

少なくとも次を内部エラーコードとして区別する。

- ネットワーク未接続
- DNSまたは接続失敗
- TLS失敗
- 接続または読み取りタイムアウト
- HTTP 408、429、その他4xx、5xx
- レスポンスサイズ超過
- 不正UTF-8またはJSON解析失敗
- 必須年不足
- 日付、名称、重複キーなどの検証失敗
- Room保存失敗
- ドメイン再計算失敗
- 通知更新失敗
- ウィジェット更新失敗

- エラー時に既存キャッシュを削除しない。
- 祝日取得失敗をTODO保存失敗として扱わない。
- 祝日取得失敗だけを理由とするシステム通知は表示しない。
- UIには技術的例外やURLではなく、影響と暫定状態を簡潔に表示する。

## 15. アクセシビリティ

- 取得中、期限超過、暫定、失敗を色だけで表現しない。
- 警告アイコンには日本語のアクセシビリティラベルを付ける。
- 暫定計算の理由と影響をTalkBackで読み上げられるようにする。
- フォント拡大時も警告、対象日、祝日名、主要操作を欠けさせない。

## 16. 受け入れ条件

1. 平日のみTODOだけに祝日除外を適用できる。
2. 未取得年でも月曜日から金曜日で暫定計算し、TODO操作を継続できる。
3. 更新後に未確定の現在と将来だけを再計算できる。
4. 確定済み履歴、期間結果、スナップショットを変更しない。
5. 現在日の祝日追加・削除を一覧とウィジェットへ反映できる。
6. 将来通知を取り消し、追加し、経過済み通知を抑止できる。
7. Receiverが通信せず、最新キャッシュで古いアラームを再検証できる。
8. 後続処理の失敗から更新世代単位で再開できる。
9. バックアップ復元後にキャッシュを上書きせず必要年を取得できる。
10. 支援技術で暫定状態と影響を識別できる。
