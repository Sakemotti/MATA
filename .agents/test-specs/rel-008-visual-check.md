# REL-008 テーマ・最大フォント実機確認手順

- 対象試験: `REL-008`
- 状態: 合格（2026年9月9日、USER確認）
- 対象: Google Playから配信した初回リリース候補
- 結果記録先: [初回Closed testing実施台帳](closed-testing-log.md)

## 1. 完了条件

1台以上のスマートフォン実機で、次の4条件すべてについて第5節の全行を確認する。

| 条件ID | アプリのテーマ | 端末のフォントサイズ | 端末の表示サイズ |
| --- | --- | --- | --- |
| VD-1 | ライト | 標準 | 標準 |
| VD-2 | ダーク | 標準 | 標準 |
| VD-3 | ライト | 端末設定で選べる最大 | 端末設定で選べる最大 |
| VD-4 | ダーク | 端末設定で選べる最大 | 端末設定で選べる最大 |

加えて、アプリのテーマを「端末設定に従う」にし、表示中に端末をライトからダーク、ダークからライトへ切り替え、再起動せずに追従することを確認する。

全行が合格し、次の条件を満たした時点で`REL-008`を合格とする。

- 内容、状態および主要操作が画面外へ失われない。
- 文字、アイコン、ボタン、ダイアログ、広告およびシステム領域に、意味や操作を損なう重なりや切れがない。
- スクロールできる領域は末尾まで到達でき、固定領域が内容を隠さない。
- 仕様で認めたTODOタイトル・説明の最大2行省略以外に、操作判断に必要な情報が欠けない。
- ライトとダークの双方で、文字、状態、選択、エラーおよびカテゴリを識別できる。

横画面、タブレット、分割画面およびTalkBackは別の環境カバレッジで確認し、`REL-008`の完了条件には含めない。

## 3. テストデータ

次の状態を事前に用意する。文字数上限のデータは入力カウンターで確認する。

- カテゴリ未設定のTODO。
- 色とアイコンが異なるカテゴリを3件以上。そのうち1件は30文字のカテゴリ名。
- タイトル100文字、説明が複数行となる有効なTODO。
- 期限なし、期限前、期限超過、完了、スキップの各TODO。
- 毎日と「毎月 第X X曜日」を含む繰り返しTODO。
- 通知を複数設定したTODO。
- 過去日に完了・スキップ・未完了の履歴が存在するTODO。
- アーカイブ済みTODO。履歴ありと履歴なしを各1件。
- 今日のウィジェットへ2カテゴリ以上、3件以上のTODOが表示される状態。

広告を確認する場合も本番広告をクリックしない。広告が配信されない場合、空の広告枠が残らず主要操作が欠けないことだけを確認し、広告表示そのものは広告試験へ残す。

## 4. 共通の確認方法

各条件で次の順に行う。

1. 端末とMATAを指定されたテーマ、フォントサイズ、表示サイズにする。
2. MATAをタスク一覧から終了して起動し直す。
3. 第5節を`V01`から順に操作し、各行を`合格`、`不合格`、`対象外`のいずれかで記録する。
4. スクロール領域は先頭と末尾、ダイアログは本文と全ボタン、入力画面はキーボード表示中と非表示の双方を確認する。
5. 不合格時はその場でスクリーンショットを保存し、端末、条件ID、画面ID、再現手順および期待結果を記録する。

証跡は、条件ごとの連続した画面録画を推奨する。ファイル名は次の形式とし、個人情報やGoogleアカウントを映さない。

```text
REL-008_OWNER_<条件ID>_<端末名>_<YYYYMMDD>.mp4
REL-008_OWNER_<条件ID>_<画面ID>_<YYYYMMDD>.png
```

画面録画を残さない場合は、各条件で`V01`、`V04`、`V05`、`V08`、`V10`および`V11`のスクリーンショットを最低1枚ずつ残す。証跡はアクセスを制限した場所へ保存し、本リポジトリへ画像や動画をコミットしない。

## 7. 判定と転記

### 合格時

1. 本書の実施前記録、マトリクスおよび端末設定追従の全結果を確定する。
2. [初回Closed testing実施台帳](closed-testing-log.md)の環境カバレッジ2行を`合格`へ更新する。
3. 同台帳の試験実施記録へ`REL-008`、端末・4条件、証跡参照を1行で追加する。
4. [初回リリース試験結果](initial-release-results.tsv)の`REL-008`を、実施日、実施者`OWNER`、versionCodeおよび証跡参照付きで`合格`へ更新する。

### 不合格時

- `S0`〜`S3`を付けて1事象1Issueで記録する。
- 主要操作不能、内容消失、誤操作につながる重なり、判読不能または設定を戻せない状態は`REL-008`を不合格とする。
- 修正後は、不合格の条件と画面だけでなく、同じ条件の前後1画面および端末設定追従を再確認する。
