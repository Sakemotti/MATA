# UI・データ性能仕様

- 文書状態: 確定
- 最終更新日: 2026-08-10
- 親仕様: [性能・省電力仕様](README.md)

## 1. 応答性目標

管理された基準端末と基準データで、次を目標とする。

| 操作 | 目標 |
| --- | --- |
| タップ・選択・チェックの視覚応答 | 100ms以内 |
| 通常の端末内保存・完了操作 | p95で500ms以内 |
| 一覧・設定の初回端末内表示 | p95で1秒以内 |
| カレンダーの月切り替え | p95で500ms以内 |
| 検索条件入力から結果更新 | 入力後300msのdebounceを除きp95で500ms以内 |
| 1秒を超える可能性がある処理 | 進行中表示を行う |
| 10秒を超える可能性がある処理 | 進捗または継続中であることと中断可否を示す |

- 起動のTTID・TTFDは起動仕様の基準を正とする。
- OSや外部アプリが支配する処理時間は目標から除外し、アプリ側の停止時間を計測する。
- 目標超過を理由に操作を重複受付せず、進行中状態を表示する。

## 2. メインスレッド

- Room、DataStore、ファイル、JSON、ZIP、ネットワーク、ハッシュ、祝日解析をメインスレッドで実行しない。
- 1,000件以上を走査する可能性がある繰り返し展開、履歴集計、通知整合をバックグラウンドDispatcherで行う。
- DebugビルドでStrictModeを有効にし、メインスレッドI/Oと長時間処理を検出する。
- CoroutineのDispatcherを注入可能にし、単体試験で決定的に実行する。
- UIへ公開するStateFlowはメインスレッドで安全に購読できる最終状態とする。

## 3. Compose

- リスト項目へTODO ID、履歴ID、カテゴリIDなど永続的で一意なkeyを設定する。
- UI状態は不変データとし、変更されていない行の不要な再コンポーズを避ける。
- スクロール中に日付計算、DBアクセス、画像生成、リフレクションを行わない。
- 表示用日付、状態ラベル、カテゴリ表現はViewModelまたは安定した派生状態で算出する。
- `derivedStateOf`とメモ化は計測で効果がある場合に使用し、古い状態を保持しない。
- 大量行への個別アニメーションを行わない。
- PreviewやDebug専用計測をReleaseへ含めない。

## 4. 一覧とページング

- TODO一覧は選択日または選択カテゴリに必要な定義・状態だけを取得する。
- カレンダーは表示月の集計と選択日の明細を別クエリとし、全履歴を読み込まない。
- アーカイブ一覧と履歴はページングし、1ページ50件を初期値とする。
- アーカイブ検索は入力後300ms debounceし、前の検索要求を取り消す。
- 次ページの先読みは末尾から10件以内へ到達した時点を初期値とする。
- ページサイズと先読み値はテスト可能な定数とし、計測結果に基づいて変更できるようにする。
- 追加取得失敗時は既存ページを保持し、再試行で同じページを重複追加しない。

## 5. Roomとクエリ

- 画面表示条件、外部キー、並べ替え、履歴期間検索に使用する列へ実測に基づくインデックスを設ける。
- 一覧1行ごとに追加クエリを行うN+1を禁止する。
- カレンダー集計はSQL集約または期間単位の集約結果を用い、Kotlin側で全履歴を集計しない。
- 書き込みトランザクション内でネットワークやユーザー入力を待たない。
- 大量更新はチャンク化し、各チャンクの再開位置と冪等性を保持する。
- SQLiteのクエリプランを主要クエリと大量データで確認する。
- データ変更ストリームは画面に必要な粒度とし、無関係な変更で全画面を再構築しない。

## 6. 繰り返し計算

- 無期限TODOを将来へ無限展開しない。
- 一覧、通知、ウィジェットは必要期間と次回候補だけを計算する。
- 同一TODO、定義リビジョン、期間境界の計算結果を処理内で再利用する。
- タイムゾーン、週開始、カテゴリ終了時刻、定義リビジョンが変わった場合は関連キャッシュを無効化する。
- キャッシュは正データとせず、いつでもRoomと定義から再生成できるようにする。

## 7. メモリとファイル

- バックアップ、復元、ハッシュ、ZIPはストリーミング処理とする。
- 大きなJSON、全履歴、全通知を単一の文字列またはコレクションへ展開しない。
- Cursor、Stream、ParcelFileDescriptor、広告、Billing接続はライフサイクルに従って閉じる。
- 画面離脱後のCoroutine、Flow購読、広告オブジェクトを保持しない。
- Bitmapを追加する場合は表示サイズへ合わせ、TODO一覧へユーザー画像キャッシュを導入しない。
- メモリ不足時にユーザーデータを削除せず、処理を失敗させて再試行可能にする。

## 8. キャッシュ

- RoomとDataStoreを正とし、プロセスメモリキャッシュだけに永続状態を持たせない。
- キャッシュにはキー、生成元リビジョン、タイムゾーン、対象期間を含める。
- 上限のないMapまたは履歴キャッシュを作らない。
- LRU等を使用する場合は上限と無効化条件を定数化し、メモリ計測で決定する。
- 祝日キャッシュ、通知内部テーブル、ウィジェットスナップショットは各仕様の保持期間を優先する。
