# Insets・折りたたみ・入力仕様

- 文書状態: 確定
- 最終更新日: 2026-08-10
- 親仕様: [画面サイズ・適応レイアウト仕様](README.md)

## 1. Edge-to-edgeとシステム領域

- 対応する全AndroidバージョンでEdge-to-edgeを有効にする。
- ステータスバーとナビゲーションバーは透明を基本とし、アイコンの明暗を現在テーマへ同期する。
- コンテンツ背景はシステムバー背面まで描画してよいが、文字と操作要素は安全なInsets内へ配置する。
- ステータスバー、ナビゲーションバー、ジェスチャー、ディスプレイカットアウト、ウォーターフォールおよびIMEのInsetsを用途別に扱う。
- Insetsを親と子で二重に適用しない。
- スクロールコンテンツはInsetsを余白として消費し、末尾項目をシステム領域から避ける。
- フルスクリーンまたはImmersive Modeは使用しない。

## 2. IME

- Activityは`adjustResize`相当の動作とする。
- IME表示時はフォーカス中の入力欄、入力エラー、保存操作へスクロールして到達できるようにする。
- IMEとボトムシートを重ねて入力内容を隠さない。
- TODO一覧のバナー広告はIME表示中に非表示とする。
- ハードウェアキーボード接続時もソフトウェアキーボード表示を前提にしない。
- キーボード表示・非表示だけで下書き、フォーカス、選択範囲を初期化しない。

## 3. 折りたたみ端末

- Jetpack WindowManagerの`FoldingFeature`から折り目・ヒンジの位置、向き、遮蔽、分離状態を取得する。
- `isSeparating`または遮蔽するヒンジ上に、文字、主要操作、入力欄、ダイアログの中央を配置しない。
- 縦方向の分離ヒンジがあり、2ペイン条件を満たす画面では、ヒンジの左右をペインとして使用する。
- 横方向の分離ヒンジでは専用テーブルトップUIを設けず、単一ペインの安全領域として扱う。
- 折りたたみ・展開中は、現在のウィンドウサイズと`FoldingFeature`の更新に追従する。
- 折り状態、端末モデル名または「タブレット」判定だけでレイアウトを固定しない。
- 三つ折りなど未認識の形状は、一般のウィンドウサイズと安全なInsetsに基づいて表示する。

## 4. タッチとポインター

- 主要なタッチ対象は48dp以上とする。
- マウスまたはトラックパッドではクリック、ホイールスクロール、ドラッグ、ホバーを利用できるようにする。
- クリック可能要素では適切なポインターアイコンとホバー状態を表示する。
- ホバーだけで情報や操作を提供しない。
- 右クリック専用操作、ダブルクリック必須操作、中ボタン専用操作を設けない。
- 横スワイプしか存在しない機能を作らず、可視ボタンまたはメニューから同じ操作を提供する。

## 5. キーボード操作

- `Tab`と`Shift+Tab`で視覚順と意味順にフォーカスを移動する。
- `Enter`または`Space`でフォーカス中のボタン、チェック、タブ、選択項目を実行する。
- `Escape`で開いているメニュー、ドロワー、ダイアログまたはボトムシートを閉じる。
- 矢印キーでタブ、ラジオボタン、カレンダー日付および同種の選択グループを移動する。
- リストは矢印キー、Page Up / Page Downおよびホイールで移動できるようにする。
- フォーカス表示を色だけに依存させず、各テーマで識別可能にする。
- フォーカスを閉じたダイアログ、非表示ペイン、画面外の削除済み要素へ残さない。
- アプリ固有のグローバルショートカットは初回公開では設けない。

## 6. 並べ替え

- カテゴリの並べ替えはタッチドラッグとポインタードラッグに対応する。
- キーボード、TalkBack、スイッチアクセス向けに「上へ移動」「下へ移動」を提供する。
- ドラッグ開始、移動先、確定、取消を視覚とアクセシビリティ通知で示す。
- ウィンドウサイズ変更、ヒンジ状態変更、画面離脱でドラッグを継続できない場合は、未確定移動を取り消す。

## 7. 状態保持と連続性

サイズ、方向、ウィンドウ形状、ナビゲーション形式またはペイン構成が変わっても、少なくとも次を保持する。

- 現在の画面と画面階層
- TODO一覧の選択日・完了済み表示と、カテゴリ別TODO一覧の選択カテゴリ
- カレンダーの表示月、選択日、履歴のスクロール位置
- カテゴリとアーカイブ一覧の選択、検索、並べ替え、スクロール位置
- TODO・カテゴリの未保存下書き、入力フォーカス、カーソル位置、バリデーション状態
- 開いているダイアログ、シート、メニューとその入力内容
- 進行中の保存、削除、復元、購入、バックアップ処理と進捗
- 完了直後などの「元に戻す」対象と残り時間

- サイズクラス変更を理由にRoomから全データを再読み込みしない。
- ViewModelの画面状態を再利用し、レイアウト構造だけを組み替える。
- プロセス再生成では保存可能な画面状態を`SavedStateHandle`等から復元し、永続処理は一意な処理IDで再接続する。
- 2ペインから単一ペインへ変わる場合、選択中の詳細があれば詳細を表示し、戻る操作で一覧へ戻す。
- 単一ペインから2ペインへ変わる場合、現在の一覧と詳細を対応する左右ペインへ表示する。

## 8. アクセシビリティ

- フォント倍率200%と表示サイズ拡大で、主要情報と操作を欠落させない。
- 固定高さへ文字を押し込まず、必要に応じて行高とコンポーネント高を拡張する。
- 画面サイズ変更後もTalkBackの読み上げ順とフォーカス位置を意味的に維持する。
- 2ペインでは左から右、上から下の順を基本とし、現在の操作対象を先に読み上げる必要があるダイアログを最前面にする。
- ナビゲーション形式が変わっても項目名、役割、選択状態を同一にする。
