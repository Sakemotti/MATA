# MATA ウィジェット更新・テスト仕様

- 文書状態: 初版
- 最終更新日: 2026-08-10
- 対応する決定事項: ウィジェット質問 55～67、82～92、99～105

## 1. WidgetUpdater

ウィジェット更新をWidgetUpdaterへ集約する。

- 画面、ViewModel、Repository、ReceiverがGlanceAppWidget.updateAllを個別に直接呼ばない。
- WidgetUpdaterは更新要求を固有WorkManager処理へまとめる。
- Work開始時に最新のRepository状態を取得する。
- 全インスタンスのサイズと一時状態を読み、各表示を更新する。
- 同じ更新要求を複数回実行してもデータ状態を変更しない。

## 2. データ変更による更新

次のトランザクション成功後に全ウィジェットを更新する。

### 2.1 TODO

- 登録
- 編集
- 完了
- 完了取り消し
- スキップ
- アーカイブ
- 復元
- 完全削除

### 2.2 カテゴリ

- 登録
- 編集
- 削除
- 並べ替え
- 一日の終了時刻変更

### 2.3 設定

- カテゴリ未設定の共通終了時刻変更
- 週の開始曜日変更
- テーマ変更
- バックアップ復元

画面上の一時的な表示切り替えだけでは更新しない。完了済み表示設定は、完了済みを常に除外するウィジェットへ影響しない。

## 3. 時刻による更新

### 3.1 次回更新候補

各更新の完了後、次のうち現在時刻より後で最も早い時点を求める。

- 表示中TODOの次の期限
- カテゴリごとの現在論理日終了
- カテゴリ未設定の現在論理日終了
- 端末の次のカレンダー日変更
- 回数指定TODOの期間境界
- 15秒の取り消し表示期限

### 3.2 WidgetRefreshAlarm

- ウィジェット更新専用の通常アラームを最大1件だけ登録する。
- 正確なアラーム権限を要求しない。
- 更新のためだけに端末を必ず起こさない非wakeup方式を使用する。
- 遅延して端末が起動した場合は、その時点の現在時刻で再計算する。
- 経過した境界を順番に表示せず、最新状態へ直接更新する。
- 更新後に次の候補へ登録し直す。

## 4. 定期整合

- updatePeriodMillisは0とする。
- 最初のウィジェット配置時に1時間ごとの固有PeriodicWorkを開始する。
- 最後のウィジェット削除時にPeriodicWorkを停止する。
- 定期Workは最新状態の再取得と表示更新を行う。
- 定期Workの遅延をアプリ独自に回避しない。
- 正確な表示時刻は保証せず、イベント更新と通常アラームを主経路とする。

## 5. 更新要求の集約

短時間に複数の変更が発生した場合:

- 固有名のOneTimeWorkへまとめる。
- Work入力へTODOデータを渡さない。
- 最新状態をRepositoryから読み直す。
- 古いスナップショットを順番に描画しない。
- 最終的なデータ状態を1回描画する。

完了後の即時反映などユーザー操作への応答では、ActionCallback内から対象インスタンスを先に更新し、その後に全件更新を要求できる。

## 6. システムイベント

次の場合に現在配置されている全ウィジェットを再構成する。

- 端末再起動
- ユーザーの初回ロック解除
- アプリ更新
- 端末時刻変更
- タイムゾーン変更
- バックアップ復元
- 祝日キャッシュ更新

再構成時:

- 経過済み更新を再生しない。
- 新しい現在時刻とZoneIdで各カテゴリの論理日を算出する。
- 確定済み履歴を変更しない。
- WidgetRefreshAlarmを登録し直す。
- 配置インスタンスがなければ更新WorkとAlarmを登録しない。

## 7. ウィジェットライフサイクル

### 7.1 最初の配置

onEnabledまたは最初のonUpdateで次を行う。

- 初回スナップショットを取得する。
- 全インスタンスを描画する。
- 1時間ごとのPeriodicWorkを開始する。
- 次回WidgetRefreshAlarmを登録する。

### 7.2 サイズ変更

- AppWidgetOptions変更をGlanceへ反映する。
- SizeMode.Responsiveにより最も近いレイアウトを選択する。
- TODOデータを再計算せず、必要なら保存済みスナップショットを再描画する。

### 7.3 インスタンス削除

- 対象WidgetInstanceStateを削除する。
- 対象インスタンスの取り消し期限Workを取り消す。
- 他インスタンスへ影響させない。

### 7.4 最後の削除

onDisabledで次を行う。

- PeriodicWorkを停止する。
- WidgetRefreshAlarmを取り消す。
- 残存するWidgetInstanceStateを整理する。
- TODO、カテゴリ、履歴などの本体データは変更しない。

## 8. データ取得

- GlanceのprovideGlanceでメインスレッドを塞がない。
- RoomとDataStoreの読み取りを適切なDispatcherで行う。
- 1回の更新では整合したデータスナップショットを取得する。
- 大量TODOを扱う処理はWorkManagerへ分離する。
- 更新中にネットワーク通信を行わない。
- 祝日は端末内キャッシュだけを使用する。
- 祝日取得はアプリ共通処理の責務とする。

## 9. 更新失敗

### 9.1 データ取得失敗

- 最後の正常スナップショットをstaleとして表示する。
- エラーコードと失敗時点をインスタンス状態へ保存する。
- 一時的な失敗はWorkManagerのバックオフで再試行する。
- データなしの場合はエラー専用表示にする。

### 9.2 Glance更新失敗

- 他インスタンスの成功を取り消さない。
- 失敗したインスタンスを再試行対象とする。
- 次の定期整合でも再試行する。
- 無限に即時再試行しない。

### 9.3 途中終了

- WidgetDisplayModel完成後にスナップショットを置き換える。
- 部分的なカテゴリまたはTODO一覧を正常スナップショットとして保存しない。
- Workが強制終了された場合は前回正常スナップショットを維持する。

## 10. 配置とバックアップ

- ホーム画面の標準ウィジェット選択画面から追加する。
- 初版ではアプリ内のピン留め操作を設けない。
- 初回設定Activityを設けない。
- 配置情報はランチャーとAppWidgetManagerを正とする。
- 配置情報とWidgetInstanceStateを手動バックアップへ含めない。
- 手動バックアップ復元後は、現在配置されているインスタンスを復元データで更新する。

## 11. プレビュー

ウィジェット選択画面に日本語の名称と説明を表示する。

- Android 15以降ではGlanceの生成プレビューを提供する。
- Android 14以前向けに静的プレビュー画像またはレイアウトを提供する。
- 実際のTODOデータをプレビューへ使用しない。
- 日本語の固定サンプルTODO、カテゴリ、期限を表示する。
- ライト・ダーク双方で確認する。
- プレビューと実際の推奨4×3レイアウトを大きく乖離させない。

## 12. デバッグ診断

デバッグ版だけに次を確認できる診断情報を用意する。

- 配置インスタンスID
- 現在サイズと選択レイアウト
- スナップショットバージョン
- 最終正常更新時刻
- loadStateとerrorCode
- 次回WidgetRefreshAlarm
- PeriodicWork状態
- 取り消し表示期限

公開版では診断入口を表示しない。タイトルや説明などのユーザー入力を診断ログへ不要に複製しない。

## 13. テスト

### 13.1 レイアウト

- 2×2
- 推奨4×3
- 横長
- 縦長
- ランチャーが許可する最大サイズ
- ライト・ダーク
- 通常・最大フォント倍率

### 13.2 データ

- TODOなし
- 1件
- 大量件数
- 長いタイトル
- カテゴリ未設定
- 全カテゴリ
- カテゴリごとに異なる論理日
- 翌日扱いの期限
- 期限超過
- 週X回・月X回の進捗

### 13.3 操作

- 完了
- 完了連打
- 15秒以内の元に戻す
- 15秒経過後の元に戻す
- 通知とウィジェットからの同時完了
- 画面とウィジェットからの同時完了
- 古い表示スナップショットからの操作
- 削除、アーカイブ、スキップ後に残った行の操作

### 13.4 ライフサイクル

- 複数ウィジェット
- 1つだけ削除
- 最後のインスタンス削除
- サイズ変更
- アプリプロセス終了
- 端末再起動
- アプリ更新
- 時刻・タイムゾーン変更
- テーマ・フォント変更
- バックアップ復元

### 13.5 障害

- Room読み取り失敗
- DataStore読み取り失敗
- 更新Work失敗
- 更新途中のプロセス終了
- 通常アラームの遅延
- 古いスナップショット付きエラー
- 正常スナップショットなしのエラー

### 13.6 ランチャー

複数メーカーまたは代表的な複数ランチャーで次を実機確認する。

- ウィジェット選択画面の名称とプレビュー
- 初期サイズ
- 最小・最大サイズ
- 縦スクロール
- ヘッダー、カテゴリ、TODO、完了ボタンのタップ
- フォント倍率

### 13.7 性能

大量TODOで次を計測する。

- RemoteViewsのデータサイズ
- データ取得時間
- Glance更新時間
- 最大メモリ使用量
- WorkManager実行時間
- Alarm登録数
- バッテリー消費

上限超過または性能問題が判明した場合は、「全件表示」というプロダクト仕様を勝手に変更せず、データ供給方式と描画方式を改善する。

## 14. 受け入れ条件

1. データ変更後に全インスタンスを最新状態へ更新できる。
2. 期限、論理日、カレンダー日の境界後に表示を更新できる。
3. 更新要求を集約し、短時間に重複Workを増やさない。
4. 最初の配置と最後の削除に合わせて定期処理を開始・停止できる。
5. 再起動、アプリ更新、時刻・タイムゾーン変更後に表示を再構成できる。
6. 更新失敗時に部分データを正常状態として表示しない。
7. プレビューと実ウィジェットの内容・外観が対応している。
8. 複数サイズ、複数インスタンス、主要ランチャーで操作できる。
9. 大量TODOでも全件へアクセスでき、性能値を測定できる。
