# MATA ウィジェット操作仕様

- 文書状態: 初版
- 最終更新日: 2026-08-26
- 対応する決定事項: ウィジェット質問 33～54、81、93

## 1. 操作範囲

ウィジェットでは次を提供する。

- TODO一覧を開く
- カテゴリ別TODO一覧を開く
- TODOを完了する

次は提供しない。

- TODO登録
- TODO編集
- スキップ
- 完了・スキップの取り消し
- アーカイブ
- 削除
- 長押し操作
- スワイプ操作
- カテゴリ管理

## 2. アプリを開く

### 2.1 ヘッダーと空状態

- ヘッダーをタップすると、現在日を選択したTODO一覧の日付別表示を開く。
- 空状態またはエラー状態をタップしてもTODO一覧を開く。

### 2.2 カテゴリ見出し

カテゴリ見出しをタップすると独立したカテゴリ別TODO一覧を開き、対象カテゴリを選択する。カテゴリ未設定の場合はカテゴリ未設定タブを選択する。

### 2.3 TODOタイトル

TODOタイトルをタップすると、対象論理日を選択したTODO一覧を開く。

- 対象論理日が現在または未来なら通常表示。
- アプリ起動までに過去日になった場合は読み取り専用表示。
- 既存のMATAタスクがあれば再利用する。
- 同じ画面をバックスタックへ重複して積まない。

Activity起動にはGlanceのactionStartActivityを使用し、ServiceまたはBroadcastReceiverを経由したActivity起動のトランポリンを設けない。

## 3. 完了ボタン

### 3.1 表示

- 未完了を示す円形の画像ボタンとする。
- 全対応APIでクリック可能なGlance Imageとして実装する。
- Android 12以降では可能な範囲でチェックボックス表現へ合わせる。
- 「TODOタイトルを完了にする」という日本語ラベルを設定する。

### 3.2 ActionCallback

GlanceのactionRunCallbackを使用し、ActionParametersには少なくとも次を含める。

- TODO ID
- 対象論理日
- TODO定義リビジョン
- ウィジェットインスタンスID
- 表示スナップショットバージョン

ActionParameters内のタイトル、状態、期限を正しい値として信用しない。Repositoryから最新状態を取得する。

### 3.3 再検証

完了前に次を検証する。

- TODOが存在する。
- アーカイブされていない。
- 定義リビジョンと現在定義の関係を確認できる。
- 対象論理日が現在も有効。
- 実行対象である。
- 完了またはスキップ済みではない。
- 回数指定TODOが未達成。

古い表示スナップショットから操作された場合も最新データを正とする。

### 3.4 完了処理

1. 操作ごとに一意のoperationIdを生成する。
2. Repositoryの共通完了処理を呼ぶ。
3. 完了記録と進捗をトランザクションで更新する。
4. 同じTODO・同じ論理日の通知を取り消す。
5. 必要回数達成時は現在期間の将来通知を取り消す。
6. TODO一覧、カレンダー、通知、全ウィジェットを更新する。

完了前の確認画面は表示しない。

## 4. 冪等性と競合

- operationIdの一意制約を使用する。
- TodoExecutionEntityのtodoId・logicalDate一意制約を使用する。
- 連打、別ウィジェット、画面、通知からの同時操作で重複完了を作らない。
- 最初に成功したトランザクションを正とする。
- ウィジェット更新は直列に実行し、後から要求された更新が古いスナップショットに上書きされないようにする。
- 異なるTODOを連続して完了した場合、各完了後に最新のRepository状態を読み直し、完了済みの全TODOを除外した一覧を最終表示とする。

再検証結果:

| 状態 | 挙動 |
| --- | --- |
| すでに完了済み | 成功相当として最新表示へ更新 |
| 削除済み | エラーを増やさず行を除去 |
| アーカイブ済み | エラーを増やさず行を除去 |
| スキップ済み | エラーを増やさず行を除去 |
| 対象外へ編集済み | エラーを増やさず行を除去 |
| DB一時エラー | 行を残して失敗表示 |

## 5. 完了成功後

- 全ウィジェットのTODOデータを更新する。
- 対象TODOを一覧から除去する。
- 完了確認メッセージや「元に戻す」操作を表示せず、全インスタンスに通常の最新一覧だけを表示する。

週X回・月X回:

- 達成した場合は現在期間の行を非表示にする。
- 未達成なら次の論理日に再表示する。
- 完了数と必要回数を更新する。

## 6. 完了・スキップの取り消し

- ウィジェットには、完了またはスキップを取り消す操作を表示しない。
- 現在の有効期間内に属する完了またはスキップの取り消しは、カレンダー履歴画面だけから行う。
- カレンダー履歴画面で取り消しが確定した場合は、全ウィジェットを最新状態へ更新する。

## 7. 失敗

完了処理が一時的なエラーで失敗した場合:

- TODO行を残す。
- 「完了できませんでした」と表示する。
- アプリを開く操作を表示する。
- 自動的に完了扱いにしない。
- 通知を取り消さない。

Widget ActionCallbackで完了できない長時間処理が必要になった場合はWorkManagerへ引き継ぐ。

## 8. ウィジェットインスタンス状態

WidgetInstanceStateEntityまたは同等の永続状態を、ウィジェットインスタンスごとに持つ。

| 項目 | 意味 |
| --- | --- |
| appWidgetIdまたはGlanceId | インスタンス識別子 |
| snapshotVersion | 表示スナップショット形式 |
| snapshotJson | 最後に正常取得したWidgetDisplayModel |
| lastSuccessAt | 最終正常更新時点 |
| loadState | loading、ready、stale、error |
| errorCode | ユーザーデータを含まない失敗理由 |

- プロセス終了後も復元できる場所へ保存する。
- 手動バックアップへ含めない。
- ウィジェット削除時に該当インスタンスの状態を削除する。
- 最後のウィジェット削除時に残存状態がないことを確認する。
- 旧バージョンとのデータベース互換性のため残る取り消し用列は常に未使用値とし、表示や操作の判定に使用しない。

## 9. 複数インスタンス

- TODOデータ変更後はすべてのインスタンスを更新する。
- サイズは各インスタンスのAppWidgetOptionsに従う。
- 一時エラー表示は対象インスタンスごとに管理する。
- どのインスタンスから操作しても同じRepository状態へ反映する。

## 10. 受け入れ条件

1. ヘッダー、カテゴリ、TODOから仕様どおりのTODO一覧を開ける。
2. 完了ボタンから確認画面なしでTODOを完了できる。
3. 連打や通知との同時操作でも完了記録が重複しない。
4. 完了後に全ウィジェットからTODOが消える。
5. 完了後に完了確認メッセージや取り消し操作を表示しない。
6. 古いスナップショットから無効なTODOを変更しない。
7. 一時エラーと対象無効を区別して表示更新できる。
8. プロセス終了後も一時エラー状態と最後の正常表示を復元できる。
