# エラー処理・障害回復の試験仕様

- 文書状態: 確定
- 最終更新日: 2026-08-10
- 親仕様: [エラー処理・障害回復仕様](README.md)

## 1. 試験方法

- Repository、外部SDK、Clock、ネットワーク、ストレージをFakeへ置き換え、各失敗型を決定的に発生させる。
- 単体試験で例外から失敗型、失敗型からUI状態への変換を網羅する。
- UI試験で読み込み、空、内容、再取得、送信中、回復可能、遮断の各状態を確認する。
- 結合試験でRoomトランザクション、WorkManager再試行、プロセス再生成および同時操作を確認する。
- 実機試験でオフライン、容量不足、権限拒否、バックグラウンド化、強制終了を確認する。

## 2. 必須障害ケース

- 初回読取、再取得、保存、完了、取消、スキップ、アーカイブ、復元、完全削除の失敗
- 対象の削除済み、リビジョン競合、同時操作
- 通信切断、タイムアウト、DNS失敗、サーバー一時障害、恒久エラー
- 通知権限拒否、正確なアラーム利用不可、外部画面から設定変更なしで復帰
- 空き容量不足、ファイル選択取消、書込先取消、破損バックアップ
- DBオープン失敗、移行失敗、整合性失敗
- Activity再生成、プロセス終了、端末再起動
- 同じIntent、通知操作、ウィジェット操作、Work要求の重複
- Snackbar、ダイアログ、画面エラー表示中のサイズ変更とTalkBack

## 3. データ保全確認

- 失敗したトランザクションが部分更新を残さない。
- 再試行または重複要求で履歴、通知、バックアップ処理が重複しない。
- 画面の楽観的更新が失敗時に確定データへ戻る。
- DB障害時にファイルを自動削除しない。
- オフラインから復帰しても過去履歴を再計算または改変しない。
- 古い非同期結果が新しい入力、選択または状態を上書きしない。

## 4. アクセシビリティ確認

- 入力エラーが項目名、内容、修正方法とともに読み上げられる。
- 新しい遮断エラーと処理結果を一度だけ認識できる。
- 色を除いてもエラー、警告、成功を識別できる。
- キーボードとスイッチアクセスから再試行、戻る、設定を開く操作を実行できる。
- フォント倍率200%でメッセージと操作が欠けない。

## 5. 受け入れ条件

1. 技術例外を定義済みの失敗型へ変換し、UIへ例外詳細を露出しない。
2. 入力、非遮断、初期取得、遮断、継続状態を適切な表示手段で区別できる。
3. すべてのエラー表示から、ユーザーが次に行える操作を判断できる。
4. 確定前の失敗を成功として表示せず、データとUIを一貫した状態へ戻せる。
5. 同じ操作の連打、再試行、プロセス再生成でも状態変更を重複適用しない。
6. オフラインでも端末内の基本機能を継続できる。
7. 外部サービス障害がTODOの起動、閲覧、登録、完了を妨げない。
8. DBオープンまたは移行失敗時にデータを自動削除せず、更新を停止できる。
9. 長時間処理へ処理IDで再接続し、二重開始を防げる。
10. Activity再生成後にエラーや完了イベントを重複表示しない。
11. TalkBack、キーボード、最大フォントでエラー内容と回復操作を利用できる。
12. 全必須障害ケースで部分更新、履歴改変、無限再試行がない。
