# MATA ウィジェット レイアウト・表示データ仕様

- 文書状態: 初版
- 最終更新日: 2026-08-26
- 対応する決定事項: ウィジェット質問 1～32、68～84、93～98

## 1. 種類と実装方式

- Jetpack Glanceで実装する。
- ホーム画面用の「今日のTODO」ウィジェットを1種類提供する。
- ロック画面や検索画面向けの特殊カテゴリを設けない。
- 初回追加時の設定Activityを設けない。
- ウィジェットごとのカテゴリ絞り込みや表示設定を設けない。
- 複数配置時も同じTODOデータを表示する。
- 広告を表示しない。
- TODO追加ボタンと手動更新ボタンを設けない。

GlanceはRemoteViews上に構築されるため、通常のJetpack Compose UI部品を混在させない。Glance専用のBox、Column、Row、LazyColumn、Image、Textなどを使用する。

## 2. サイズ

| 項目 | 値 |
| --- | --- |
| 最小サイズ | 2×2セル |
| 推奨初期サイズ | 4×3セル |
| サイズ変更 | 横・縦の両方 |
| サイズ方式 | SizeMode.Responsive |

サイズに応じて次の3段階を用意する。

### 2.1 コンパクト

- 2×2セル程度。
- ヘッダー、未完了件数、スクロール一覧を表示する。
- カテゴリ見出しとTODO行の余白を縮小する。
- TODOタイトルと行全体の操作領域を優先する。
- 期限は必要に応じて次の行へ送る。

### 2.2 標準

- 推奨4×3セル程度。
- ヘッダー、カテゴリ見出し、タイトル、期限、回数進捗を表示する。
- 通常の基準レイアウトとする。

### 2.3 拡張

- 縦長、横長、最大サイズ。
- 表示項目は標準と同じとし、一覧の可視範囲と余白を広げる。
- データや操作種別をサイズによって追加・削除しない。

すべてのサイズでLazyColumnによる縦スクロールを使用する。表示件数にプロダクト上の上限を設けず、今日の対象TODOへ全件アクセスできるようにする。

## 3. ヘッダー

ヘッダーには次を表示する。

- 「今日のTODO」
- 全カテゴリを合計した未完了TODO件数

ヘッダー全体をタップ可能とし、TODO一覧の日付別表示を開く。

未完了件数には、ウィジェットの現在スナップショットに表示されているTODOだけを含める。

## 4. カテゴリ

### 4.1 グループ

- TODOをカテゴリごとに分ける。
- 表示対象TODOがないカテゴリの見出しは表示しない。
- カテゴリ未設定を先頭にする。
- ユーザーカテゴリはカテゴリ管理画面のsortOrderに従う。

### 4.2 見出し

次を表示する。

- カテゴリ色
- Material Icon
- カテゴリ名
- 必要な場合だけ対象論理日

カテゴリの論理日が端末の現在カレンダー日と異なる場合は「8月10日分」のように表示する。色だけに依存せず、アイコンと名前を必ず併用する。

カテゴリ見出しをタップすると、独立したカテゴリ別TODO一覧で対象カテゴリを選択する。

## 5. TODO行

### 5.1 表示項目

- タイトル
- 期限
- 期限超過表示
- 週X回・月X回の進捗

説明文は表示しない。

タイトルは通常1行とし、収まらない場合は省略記号を表示する。フォント拡大時は操作可能なTODO行とタイトルを欠けさせず、期限を次の行へ送る。

- 行内に独立した完了チェックボタンを設けない。
- TODO行全体を1つの操作領域とし、タップすると完了・スキップを選ぶ操作ダイアログ画面を開く。
- 行の最小タップ高さは48dpとし、タイトル、期限、期限超過、回数進捗の表示領域を分断しない。

### 5.2 期限

- 明示的な期限があれば計算済み期限を表示する。
- 期限未設定でもカテゴリまたは共通終了時刻を期限として表示する。
- 期限が対象論理日の翌カレンダー日なら「翌日 2:00」のように表示する。
- 期限超過後も論理日終了までは表示する。
- 期限超過は警告アイコンと「期限超過」の文字で示す。

### 5.3 回数進捗

週X回・月X回では「1/3回」のように、現在期間の完了数と必要回数を表示する。

必要回数達成済みのTODOは表示対象外となる。

### 5.4 表示対象外

次は表示しない。

- 完了済み
- スキップ済み
- アーカイブ済み
- 有効期間外
- 対象論理日の実行対象外
- 回数指定TODOの達成済み期間

## 6. 並び順

1. カテゴリ未設定
2. CategoryEntity.sortOrder
3. カテゴリ内の計算済み期限
4. TodoEntity.createdAt
5. TodoEntity.id

期限未設定TODOは、適用される一日の終了時刻を期限として並べる。同じ入力では常に同じ順序になるよう、最後にUUIDを使用する。

## 7. 表示データ

### 7.1 共通計算

- TODO一覧と通知と同じRepositoryを使用する。
- [繰り返し計算仕様](../domain-specs/recurrence-rules.md)の結果を使用する。
- Glance側で曜日、期限、論理日、回数を再計算しない。
- RoomエンティティをGlance UIへ直接渡さない。
- 不変のWidgetDisplayModelへ変換する。

### 7.2 更新コンテキスト

1回の表示データ取得では次を固定する。

- 現在時点
- ZoneId
- 共通終了時刻
- 週開始曜日
- 祝日キャッシュの状態
- 読み取り対象のデータベーススナップショット

カテゴリごとに終了時刻を適用し、現在論理日を個別に算出する。

### 7.3 WidgetDisplayModel

少なくとも次を持つ。

- スナップショットバージョン
- 作成時点
- 未完了合計件数
- カテゴリグループの安定した順序
- カテゴリIDまたはnull
- カテゴリ名、色、アイコン、論理日
- TODO ID、定義リビジョン
- TODOタイトル
- 対象論理日
- 期限表示
- 期限超過状態
- 回数進捗
- 完了アクション可否

## 8. 読み込み、空状態、エラー

### 8.1 読み込み中

初回データ取得中で、正常スナップショットがない場合は読み込み状態を表示する。一定時間を超えた場合はエラー状態へ移行する。

### 8.2 空状態

- 「今日のTODOはありません」と表示する。
- 空状態全体をタップするとTODO一覧を開く。

### 8.3 一時エラー

最後の正常スナップショットがある場合:

- 最後の正常データを維持する。
- 「更新できませんでした」と表示する。
- 最終更新時刻を表示する。
- アプリを開く操作を表示する。

正常スナップショットがない場合:

- TODOを推測表示しない。
- エラーメッセージとアプリを開く操作だけを表示する。

古いスナップショット上の操作では、必ず最新データを再取得してから状態を変更する。

### 8.4 最終更新時刻

更新成功時に最終更新時刻を保存する。通常表示では隠し、エラー状態とデバッグ診断だけに表示する。

## 9. テーマ

- Material 3を基調とする。
- 端末のライト・ダークテーマへ追従する。
- カテゴリ色はアクセントとして使用する。
- カテゴリ状態を色だけで表現しない。
- ライト・ダーク双方で文字、ボタン、期限超過表示のコントラストを確保する。

## 10. アクセシビリティ

- タップ可能領域は原則48dp以上。
- TODO行はタイトル、期限、進捗を読み上げた後、操作可能であることを通知する。
- ヘッダー、カテゴリ、TODOタイトル、期限、進捗、TODO操作を意味の通る順序で読み上げる。
- 文字サイズにはspを使用し、端末のフォント倍率を反映する。
- フォント拡大時にもTODO行の操作領域とタイトルを欠けさせない。
- アイコンだけで期限超過やカテゴリを伝えない。

## 11. 受け入れ条件

1. サイズにかかわらず今日の対象TODOを全件スクロール表示できる。
2. カテゴリごとに異なる論理日を正しく反映できる。
3. TODO一覧と同じ表示対象、期限、進捗、並び順を使用できる。
4. 完了済み、スキップ済み、アーカイブ済みを表示しない。
5. 空、読み込み、正常、古いデータ付きエラー、データなしエラーを区別できる。
6. プロセス終了後も最後の正常スナップショットを復元できる。
7. ライト・ダーク、フォント拡大、TalkBackで主要情報と操作を利用できる。
