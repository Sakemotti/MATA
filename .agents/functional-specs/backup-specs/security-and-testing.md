# MATA バックアップ安全性・テスト仕様

- 文書状態: 初版
- 最終更新日: 2026-08-10

## 1. 脅威モデル

復元対象は、壊れたファイル、別アプリが作成したファイル、意図的に細工されたZIP・JSONを含む信頼できない入力として扱う。

保護対象は次のとおり。

- 現在のTODO、カテゴリ、履歴、設定の完全性
- アプリ専用領域内の他ファイル
- 端末のメモリ、ストレージ、CPU
- バックアップに含まれる個人情報
- 復元後の通知とウィジェットの一貫性

SHA-256は破損検知だけを目的とする。同じファイル内のmanifestを書き換えられるため、悪意ある改ざんや作成元の真正性は検証できない。

## 2. 入力上限

バージョン1は次の固定上限を適用する。

| 対象 | 上限 |
| --- | --- |
| ZIPエントリ数 | 2件ちょうど |
| `manifest.json`非圧縮サイズ | 64 KiB |
| `data.json`非圧縮サイズ | 1 GiB |
| JSONネスト深度 | 64 |
| UUID文字列 | canonical表現36文字ちょうど |
| SHA-256文字列 | 小文字16進数64文字ちょうど |
| カテゴリ名 | 1～30文字 |
| TODOタイトル | 1～100文字 |
| TODO説明 | 0～1000文字 |
| TODOごとの通知設定 | 最大10件 |
| 通知差分 | 1～999、`at`だけ0 |

- 1 MiB以上のエントリで、申告または実測した非圧縮サイズが圧縮サイズの200倍を超える場合は異常な圧縮率として拒否する。
- ZIPヘッダーのサイズが既知で、負数、オーバーフロー、上限超過の場合は拒否する。
- ストリーミング出力でヘッダーのサイズが未確定の場合は、それだけを理由に拒否せず、読み取り中の実測値へ上限を適用する。
- ヘッダー値を信用せず、ストリーミング中の実測値が上限を超えた時点で中止する。
- アプリ専用一時領域の利用可能容量が、必要な非圧縮データと回復用データを安全に保持できない場合は復元を開始しない。
- 加算と乗算はオーバーフローを検出する型と処理で行う。
- 配列件数はmanifestの非負整数、実際の要素数、保存層が扱える件数のすべてを満たす必要がある。
- 各フィールドには[形式仕様](format-v1.md)とドメイン仕様のより厳しい上限を適用する。

上限を将来変更する場合は互換性影響を確認する。作成済みの正当なバージョン1ファイルを新しいアプリが理由なく拒否しないよう、緩和は可能だが厳格化には形式移行または互換性方針を必要とする。

## 3. ZIP対策

- ZIPをファイルシステムへ汎用展開しない。
- 許可したエントリ名との完全一致で処理する。
- 絶対パス、ドライブ文字、UNC、`..`、パス区切り、NULを含む名前を拒否する。
- 重複名、大小文字だけ異なる重複、未知エントリ、暗号化エントリ、対応外圧縮方式、分割ZIPを拒否する。
- ZIP64はサイズがバージョン1の上限内で、使用ライブラリが安全に検証できる場合だけ許可する。
- CRC、非圧縮サイズ、圧縮サイズ、実際の読み取りバイト数を照合する。
- ZIP bomb対策としてサイズと圧縮率を読み取り中にも監視する。
- エントリ名から出力先パスを組み立てない。

## 4. JSON対策

- Kotlin Serializationの厳格な設定または同等のストリーミングデコーダーを使用する。
- 未知フィールドを無視しない。
- 重複キーを後勝ちまたは先勝ちで受け入れない。
- 数値から文字列、文字列から数値などの暗黙変換を行わない。
- 整数に小数、指数表記、範囲外、オーバーフローを許可しない。
- 不正なUnicode、不正なUTF-8、BOM、制御文字を拒否する。
- 文字数はUnicodeコードポイントを基準に画面入力仕様と同じ方法で検証する。
- JSON深度、配列件数、文字列長を解析中に監視する。
- 値検証後もID参照、一意条件、集計値などデータ全体の意味検証を行う。

## 5. 一時ファイルとログ

- 一時データとロールバックデータはアプリ専用領域に作成する。
- ファイル名には処理IDだけを使用し、TODOタイトルや外部ファイル名を含めない。
- 通常のAndroid自動バックアップ対象から除外する。
- 処理成功、失敗、強制終了後の回復で削除する。
- ログへタイトル、説明、履歴スナップショット、外部URI、JSON本文、ハッシュを出力しない。
- 診断ログには処理ID、形式バージョン、段階、分類済みエラーコード、件数だけを残せる。

## 6. プライバシー表示

- 作成前に、バックアップへ個人情報が含まれる可能性を表示する。
- アプリ独自には暗号化されないことを表示する。
- 公開共有フォルダではなく、安全な保存先を選ぶよう案内する。
- バックアップ内容をMATAのサーバーへ送信しない。
- バックアップ・復元完了後に選択URIへの権限を保持し続けない。

## 7. 単体テスト

### 7.1 形式

- 空データの正規JSONとmanifest
- 全データ種別を含む正規JSON
- 同一入力から同一の`data.json`が生成されること
- JSONの出力後読み込みによる往復一致
- 非圧縮バイト数、SHA-256、件数
- UUID、日時、日付、null、列挙値の表現
- JSON文字列を入れ子オブジェクトへ変換し、二重エンコードしないこと

### 7.2 データパターン

- すべての繰り返し方式と方式固有パラメータ
- カテゴリ未設定とカテゴリ所属TODO
- 通常TODOとアーカイブ済みTODO
- 完了、スキップ、確定済み未完了
- 週X回・月X回の達成、未達成、必要回数を超えた完了数
- 複数通知と通知なし
- 有期限、無期限、期限あり、期限なし
- 履歴スナップショットの全対応バージョン
- 実行状態の各カーソル
- 共通終了時刻、全曜日、完了表示、全テーマ

### 7.3 対象外

次が出力されず、復元でも上書きされないことを確認する。

- Google Play購入状態
- 祝日キャッシュと取得状態
- OS通知登録情報と表示中通知
- ウィジェット配置、サイズ、スナップショット
- 一時UI、下書き、ログ、キャッシュ

## 8. 不正ファイルテスト

- ZIPでないファイル
- 空、途中切断、中央ディレクトリ破損
- 必須エントリ不足、順序違い、重複、未知エントリ
- 絶対パス、`..`、区切り文字、大小文字違いを含むエントリ名
- CRC不一致、SHA-256不一致、非圧縮サイズ不一致
- manifestまたはdataの上限超過
- ZIP bomb相当の圧縮率
- JSON深度超過、巨大文字列、巨大配列
- 不正UTF-8、BOM、不正JSON、重複キー、未知フィールド
- 必須項目不足、型違い、null違反、数値範囲外、整数オーバーフロー
- 不正UUID、ID重複、operation ID重複、参照先不足
- カテゴリ正規化名重複、sortOrder重複または欠番
- TODO・通知・履歴・期間結果・実行状態の一意条件違反
- repeatTypeとrepeatParamsの不一致
- snapshotVersionとsnapshot構造の不一致
- periodの境界、件数、achievedの不一致
- manifest件数とdata件数の不一致

すべてのケースで、現在データを変更せず、一時データを後始末できることを確認する。

## 9. 互換性テスト

- 形式バージョンごとに小規模、全機能、大規模のゴールデンファイルを保持する。
- 現行バージョンを現行実装で復元できる。
- 対応する各旧バージョンから現在モデルへ段階的に移行できる。
- 各移行段階で値、件数、参照、スナップショットを検証できる。
- 未対応の新しい`formatVersion`を拒否する。
- バージョン1の曜日指定を任意曜日、週X回を期間週数1・すべての日として復元する。
- バージョン2のN週間にX回について期間週数、必要回数、平日、土日祝、任意曜日を往復する。
- バージョン2の未知`dayFilter`、空の任意曜日、範囲外の期間週数・必要回数を拒否する。
- 未対応の`minimumReaderVersion`を拒否する。
- 作成時のアプリバージョンまたはRoomスキーマが異なっても、形式が対応済みなら復元できる。
- 公開済み列挙コードとフィールドの意味が変更されていないことをCIで確認する。

## 10. 障害注入テスト

次の各段階で失敗またはプロセス終了を注入する。

- 出力URIを開く前後
- `data.json`の先頭、中間、末尾
- manifest書き込み前後
- ZIP finishとclose
- 作成後の読み直し検証
- 復元ファイルのコピーと構造検証
- 意味検証と旧形式移行
- ロールバック用スナップショット作成
- Room削除、各データ種別の挿入、Roomコミット
- DataStore更新前後
- 通知取消、整合処理、通知再登録、ウィジェット更新
- 一時ファイル削除、URI権限解放、ジャーナル完了

各失敗で次を確認する。

- バックアップ作成失敗では端末内データが変わらない。
- 復元失敗では復元前または復元完了の一方だけになる。
- 部分データを通常UIへ公開しない。
- 再起動後の回復処理を複数回実行しても結果が変わらない。
- 旧データへ戻した場合は旧データの将来通知とウィジェットを再構築できる。
- 一時ファイル、権限、排他ロックを解放できる。

## 11. ストレージ・Providerテスト

- 端末内のDocumentsProvider
- 代表的なクラウド対応DocumentsProvider
- 読み取り専用の場所
- 書き込み途中の容量不足
- アプリ専用一時領域の容量不足
- Provider切断、タイムアウト、権限喪失
- 保存先選択と復元ファイル選択のキャンセル
- 同名ファイルに対するProvider固有動作
- 不完全ファイルをProviderが削除できる場合とできない場合
- サイズ情報を返さないProvider
- 低速なProviderとアプリのバックグラウンド移行

## 12. 性能テスト

- 空データ、通常規模、上限に近い大規模データを使用する。
- 作成と復元のピークメモリが総データサイズに比例して増えないことを確認する。
- ストリーミング中に入力上限を超えた時点で処理を停止できることを確認する。
- 長時間Workerへの移行、進捗再購読、停止要求への応答を確認する。
- 端末再起動またはプロセス終了後の回復時間を計測する。

## 13. 統合・受け入れテスト

1. 設定画面からバックアップを作成し、別の初期状態へ完全復元できる。
2. 復元後のTODO、カテゴリ、履歴、期間結果、対象設定が作成時と一致する。
3. 確定済み履歴の論理日とスナップショットが現在時刻や設定変更で変化しない。
4. 復元時点の端末時刻とタイムゾーンで現在・将来だけを再計算できる。
5. 経過済み通知を発火させず、将来通知だけを再登録できる。
6. 全ウィジェットへ復元結果を反映できる。
7. 購入状態と祝日キャッシュをバックアップ値で上書きしない。
8. 破損ファイルと未対応形式を現在データの変更前に拒否できる。
9. 復元失敗と強制終了から一貫した状態へ回復できる。
10. ライト・ダーク、フォント拡大、TalkBackで警告、確認、進捗、成功、失敗を利用できる。
