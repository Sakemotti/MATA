# MATA 通知表示・操作仕様

- 文書状態: 初版
- 最終更新日: 2026-08-10
- 対応する決定事項: 通知質問 1～5、13～26、57～86、121～135

## 1. 通知権限

### 1.1 POST_NOTIFICATIONS

Android 13以降ではPOST_NOTIFICATIONSを宣言し、実行時に要求する。

- 初回起動時には要求しない。
- ユーザーが初めて通知付きTODOを保存するときに要求する。
- システムダイアログの前に、TODOを指定時刻に知らせるための権限であることを説明する。
- 拒否またはダイアログを閉じた場合も、TODOと通知設定を保存する。
- 拒否後にTODO保存のたびに再要求しない。
- 設定画面からAndroidの通知設定を開けるようにする。
- 権限状態は保存値ではなくAndroidから取得する。

Android 12L以前ではPOST_NOTIFICATIONSの実行時要求を行わない。

### 1.2 正確なアラーム

- USE_EXACT_ALARMではなくSCHEDULE_EXACT_ALARMを使用する。
- 通知権限とは別に、正確な時刻で知らせるための特別なアクセスであることを説明する。
- 許可がなくてもTODOと通知設定の保存を妨げない。
- 通知付きTODOがある場合だけ設定画面へ案内する。
- 拒否または取消時は通常アラームへフォールバックする。
- 許可状態はcanScheduleExactAlarmsで取得する。

## 2. 通知チャンネル

初版では1つのチャンネルを使用する。

| 項目 | 値 |
| --- | --- |
| チャンネルID | todo_reminders_v1 |
| 表示名 | TODO通知 |
| 初期重要度 | DEFAULT |
| 用途 | 期限前、期限時刻、期限超過、終了境界 |

- 音、振動、ロック画面表示、Do Not DisturbはAndroidの設定を正とする。
- アプリ独自の通知音、振動、通知一括オン・オフを設けない。
- チャンネルを削除・再作成してユーザー設定を初期化しない。
- 将来チャンネルの性質を大きく変える場合は新しいIDを追加する。
- ユーザーが無効化したチャンネルをアプリから回避しない。

## 3. 個別通知

### 3.1 表示内容

| 領域 | 内容 |
| --- | --- |
| 小アイコン | MATAの通知用モノクロアイコン |
| タイトル | TODOタイトル |
| 本文 | カテゴリ名、対象論理日、期限状態 |
| アクセント | カテゴリ色 |
| 公開範囲 | VISIBILITY_PRIVATE |
| 消去 | ユーザーが消去可能 |

説明欄の全文は通知へ表示しない。カテゴリ未設定は「カテゴリ未設定」と明示し、色だけに依存しない。

対象論理日は日本語日付で表示する。事前通知が前日以前に届いても、どの日のTODOか識別できることを優先する。

### 3.2 状態文言

- 期限前: 「期限まであと30分」
- 期限時刻: 「期限時刻です」
- 期限超過: 「期限を1時間過ぎています」
- 終了境界: 「この日の期限になりました」
- 週X回・月X回: 上記に加えて「1/3回完了」

AlarmManagerの遅延により設定時の種別と現在状態が異なる場合は、受信時点の状態に合わせて本文を更新する。

### 3.3 フォアグラウンド

MATAがフォアグラウンドであっても通知を表示する。現在表示している画面によってシステム通知を抑止しない。

## 4. グループ

- 個別TODOごとに通知を作成する。
- 同時に複数件ある場合はMATA共通のgroupKeyでまとめる。
- グループ要約には未処理件数を表示する。
- グループ要約へ一括完了操作を設けない。
- 個別通知の完了、取消、消去に応じて件数を更新する。
- 個別通知がなくなった場合はグループ要約も削除する。

## 5. 通知本体のタップ

### 5.1 遷移

- 対象論理日を選択したTODO一覧を開く。
- 対象論理日が現在または未来なら通常の一覧を開く。
- 対象論理日が過去なら読み取り専用表示を開く。
- 既存のMATAタスクがあれば再利用する。
- 同じ画面をバックスタックへ重複して積まない。
- 戻る操作で通常のアプリ内ナビゲーションへ復帰できる。

PendingIntentにはプロセス終了後も復元できるよう、TODO ID、対象論理日、候補キーを含める。画面表示時はデータベースから最新内容を再取得する。

通知は`VISIBILITY_PRIVATE`とし、ロック画面向け公開版にはアプリ名と「TODOの通知」だけを表示する。TODOタイトル、説明およびカテゴリは公開版へ含めない。詳細は[データ・プライバシー仕様](../../non-functional-specs/security-privacy-specs/data-and-privacy.md)に従う。

### 5.2 タップ後

- タップした個別通知だけを閉じる。
- TODO状態は変更しない。
- 別の通知タイミングと次回実行日の通知は維持する。

通知をスワイプして消した場合もTODO状態を変更せず、将来通知を維持する。

## 6. 完了アクション

### 6.1 表示条件

次のすべてを満たす通知へ「完了」を表示する。

- 対象TODOが未完了または期限超過
- 対象論理日が完了可能な有効期間内
- 完了またはスキップ記録がない
- 回数指定TODOが未達成
- 終了境界通知ではない

ロック画面からもAndroidの通知設定に従って操作でき、アプリ独自のロック解除を要求しない。

### 6.2 セキュリティ

- 完了用BroadcastReceiverはandroid:exportedをfalseとする。
- 明示的で変更不可能なPendingIntentを使用する。
- PendingIntent内のタイトル、状態、カテゴリなどを正しい値として信用しない。
- TODO ID、通知設定ID、論理日からデータベースの最新状態を取得する。
- Repositoryで対象を再検証する。

### 6.3 処理

1. 操作ごとに一意なoperationIdを生成する。
2. 画面とウィジェットと同じRepositoryの完了処理を呼ぶ。
3. データベーストランザクションの結果を待つ。
4. 成功時は同じTODO・同じ論理日の通知をすべて取り消す。
5. 回数指定TODOの進捗を再計算する。
6. 達成時は現在期間の残り通知を取り消す。
7. 一覧、カレンダー、ウィジェットを更新する。

画面を開かず、確認ダイアログも表示しない。

### 6.4 競合

- 連打、画面、ウィジェット、別通知との同時操作はoperationIdと実行記録の一意制約で重複を防ぐ。
- すでに完了していた場合は成功相当として通知を閉じる。
- 編集、削除、アーカイブで対象が無効なら通知を閉じ、追加エラー通知を出さない。
- 一時的なデータベースエラーでは元の通知を維持し、「完了できませんでした」と表示する。

## 7. 完了後の元に戻す

完了成功後、元の通知を15秒間の確認通知へ置き換える。

- タイトル: TODOタイトル
- 本文: 「完了しました」
- アクション: 「元に戻す」
- timeoutAfter: 15秒

元に戻す処理:

1. 対象完了が現在も取り消し可能か再検証する。
2. Repositoryの共通完了取り消し処理を呼ぶ。
3. 完了記録を削除する。
4. 回数指定TODOの進捗を再計算する。
5. 現在時刻より後の通知候補だけを再登録する。
6. 一覧、カレンダー、ウィジェットを更新する。

取り消し可能期間を過ぎていた場合はデータを変更せず、「完了を取り消せませんでした」と表示する。

## 8. Receiverの実行

- 通知操作はBroadcastReceiverで受け取る。
- ローカルDB操作だけで短時間に完了させる。
- 必要な場合はgoAsyncを使用する。
- 長時間処理が必要になった場合はWorkManagerへ引き継ぐ。
- メインスレッドをブロックしない。
- Receiver内でネットワーク通信を行わない。

## 9. requestCode

通知表示、本文タップ、完了、元に戻すには用途ごとに別のPendingIntentを使用する。

- requestCodeはScheduledNotificationEntityで永続管理する。
- 単純なハッシュ衝突によって他のTODO通知を上書きしない。
- TODO編集、取消、削除時に同じrequestCodeで正しいPendingIntentを取消できる。

## 10. 内部配信状態

配信、失効、取消、失敗はScheduledNotificationEntityへ内部状態として保持する。

- ユーザーのTODO履歴には表示しない。
- 手動バックアップへ含めない。
- 外部サーバーへ送信しない。
- 次回登録や障害調査に不要となった後、一定の保守期間で削除する。

## 11. アプリ独自で保証しない事項

- AndroidのDo Not Disturbを回避しない。
- マナーモードやユーザーが選択したサイレント設定を回避しない。
- force stop中の通知を保証しない。
- 端末メーカー独自の省電力制御を回避する特別な権限を要求しない。
- バッテリー最適化の除外を要求しない。

## 12. 受け入れ条件

1. 権限を拒否してもTODOと通知設定を保存できる。
2. 通知種別、対象日、カテゴリ、回数進捗を識別できる。
3. 同時通知を個別操作可能なグループとして表示できる。
4. 通知本体から対象日の一覧へ正しく移動できる。
5. 通知から確認画面なしで重複なく完了できる。
6. 完了後15秒間、通知から完了を取り消せる。
7. 過去または無効なTODOを通知から変更できない。
8. 通知の消去や本文タップによってTODO状態と将来通知が変わらない。
9. フォアグラウンド、ロック画面、プロセス終了後も同じ規則で動作する。
