# MATA ウィジェット操作仕様

- 文書状態: 初版
- 最終更新日: 2026-08-26
- 対応する決定事項: ウィジェット質問 33～54、81、93

## 1. 操作範囲

ウィジェットでは次を提供する。

- TODO一覧を開く
- カテゴリ別TODO一覧を開く
- TODO行から操作ダイアログ画面を開く
- TODOを完了する
- TODOをスキップする

次は提供しない。

- TODO登録
- TODO編集
- 完了・スキップの取り消し
- アーカイブ
- 削除
- 長押し操作
- スワイプ操作
- カテゴリ管理

## 2. アプリを開く

### 2.1 ヘッダーと空状態

- ヘッダーをタップすると、現在日を選択したTODO一覧の日付別表示を開く。
- 空状態またはエラー状態をタップしてもTODO一覧を開く。

### 2.2 カテゴリ見出し

カテゴリ見出しをタップすると独立したカテゴリ別TODO一覧を開き、対象カテゴリを選択する。カテゴリ未設定の場合はカテゴリ未設定タブを選択する。

### 2.3 TODO行

TODO行をタップすると、対象TODOの操作ダイアログ画面を開く。行内に独立した完了チェックボタンやタイトルだけの別操作領域を設けない。

- ホーム画面の背後を維持するため、アプリ本体とは別のタスクアフィニティを持つ非公開の専用Activityを使用する。
- Activity終了後はホーム画面へ戻り、最近使ったアプリの一覧へ専用Activityを残さない。
- TODO ID、対象論理日、定義リビジョン、ウィジェットインスタンスID、スナップショットバージョンを渡す。
- Intentに含まれるタイトルやTODO状態は正しい値として信用せず、表示前と操作直前にRepositoryから再取得する。

Activity起動にはGlanceのactionStartActivityを使用し、ServiceまたはBroadcastReceiverを経由したActivity起動のトランポリンを設けない。

## 3. 操作ダイアログ画面

### 3.1 表示

- Android標準ダイアログと同じ方式で背後を減光し、ライト・ダークテーマへ追従する。
- 全画面相当の透明な専用Activity上で、広告領域を除く残りの領域中央へダイアログ風の操作領域を表示する。
- 本文は「TODOタイトルに対する操作を選択してください。」とする。
- 「完了」「スキップ」「キャンセル」ボタンを表示する。
- 広告付き利用者には、共通の同意状態と広告表示条件を満たす場合だけ、操作領域から分離したバナー広告をシステムナビゲーション領域より上の画面下部へ固定表示する。
- バナー広告を操作領域の内側へ配置せず、本文または操作ボタンと重ねない。
- 同意未完了または広告SDK未準備の場合は広告枠を残さない。
- 戻る操作、ダイアログ風操作領域の外側タップ、キャンセルでは状態を変更せず閉じる。広告自体へのタップはキャンセル操作として扱わない。
- 操作送信中はボタンを無効化し、同じ操作を二重送信しない。

### 3.2 専用Activity

専用Activityは外部アプリから起動できない `exported=false` とし、Intentには少なくとも次を含める。

- TODO ID
- 対象論理日
- TODO定義リビジョン
- ウィジェットインスタンスID
- 表示スナップショットバージョン

Intent内のタイトル、状態、期限を正しい値として信用しない。Repositoryから最新状態を取得する。

### 3.3 再検証

完了またはスキップ前に次を検証する。

- TODOが存在する。
- アーカイブされていない。
- 定義リビジョンと現在定義の関係を確認できる。
- 対象論理日が現在も有効。
- 実行対象である。
- 完了またはスキップ済みではない。
- 回数指定TODOが未達成。

古い表示スナップショットから操作された場合も最新データを正とする。

### 3.4 状態変更処理

1. 操作ごとに一意のoperationIdを生成する。
2. 選択されたボタンに応じ、Repositoryの共通完了処理または共通スキップ処理を呼ぶ。
3. 完了記録またはスキップ記録と進捗をトランザクションで更新する。
4. 同じTODO・同じ論理日の通知を取り消す。
5. 必要回数達成時は現在期間の将来通知を取り消す。
6. TODO一覧、カレンダー、通知、全ウィジェットを更新して専用Activityを閉じる。

操作ダイアログ画面で完了またはスキップを選択した後、追加の確認画面は表示しない。

## 4. 冪等性と競合

- operationIdの一意制約を使用する。
- TodoExecutionEntityのtodoId・logicalDate一意制約を使用する。
- 連打、別ウィジェット、画面、通知からの同時操作で重複する完了・スキップを作らない。
- 最初に成功したトランザクションを正とする。
- ウィジェット更新は直列に実行し、後から要求された更新が古いスナップショットに上書きされないようにする。
- 異なるTODOを連続して完了した場合、各完了後に最新のRepository状態を読み直し、完了済みの全TODOを除外した一覧を最終表示とする。

再検証結果:

| 状態 | 挙動 |
| --- | --- |
| すでに完了済み | 成功相当として最新表示へ更新 |
| 削除済み | エラーを増やさず行を除去 |
| アーカイブ済み | エラーを増やさず行を除去 |
| スキップ済み | エラーを増やさず行を除去 |
| 対象外へ編集済み | エラーを増やさず行を除去 |
| DB一時エラー | 行を残して失敗表示 |

## 5. 操作成功後

- 全ウィジェットのTODOデータを更新する。
- 対象TODOを一覧から除去する。
- 完了確認メッセージや「元に戻す」操作を表示せず、全インスタンスに通常の最新一覧だけを表示する。

週X回・月X回:

- 達成した場合は現在期間の行を非表示にする。
- 未達成なら次の論理日に再表示する。
- 完了数と必要回数を更新する。

## 6. 完了・スキップの取り消し

- ウィジェットには、完了またはスキップを取り消す操作を表示しない。
- 現在の有効期間内に属する完了またはスキップの取り消しは、カレンダー履歴画面だけから行う。
- カレンダー履歴画面で取り消しが確定した場合は、全ウィジェットを最新状態へ更新する。

## 7. 失敗

完了またはスキップ処理が一時的なエラーで失敗した場合:

- TODO行を残す。
- 操作ダイアログ画面に「完了にできませんでした」または「スキップできませんでした」と表示する。
- 自動的に完了またはスキップ扱いにしない。
- 通知を取り消さない。

操作を完了できない長時間処理が必要になった場合はWorkManagerへ引き継ぐ。

## 8. ウィジェットインスタンス状態

WidgetInstanceStateEntityまたは同等の永続状態を、ウィジェットインスタンスごとに持つ。

| 項目 | 意味 |
| --- | --- |
| appWidgetIdまたはGlanceId | インスタンス識別子 |
| snapshotVersion | 表示スナップショット形式 |
| snapshotJson | 最後に正常取得したWidgetDisplayModel |
| lastSuccessAt | 最終正常更新時点 |
| loadState | loading、ready、stale、error |
| errorCode | ユーザーデータを含まない失敗理由 |

- プロセス終了後も復元できる場所へ保存する。
- 手動バックアップへ含めない。
- ウィジェット削除時に該当インスタンスの状態を削除する。
- 最後のウィジェット削除時に残存状態がないことを確認する。
- 旧バージョンとのデータベース互換性のため残る取り消し用列は常に未使用値とし、表示や操作の判定に使用しない。

## 9. 複数インスタンス

- TODOデータ変更後はすべてのインスタンスを更新する。
- サイズは各インスタンスのAppWidgetOptionsに従う。
- 一時エラー表示は対象インスタンスごとに管理する。
- どのインスタンスから操作しても同じRepository状態へ反映する。

## 10. 受け入れ条件

1. ヘッダーとカテゴリから仕様どおりのTODO一覧を開ける。
2. TODO行全体から操作ダイアログ画面を開き、完了・スキップ・キャンセルを選べる。
3. 行内に独立した完了チェックボタンがなく、ライト・ダーク双方でAndroid標準相当の背景減光となる。
4. 広告表示時はバナーが画面下部へ固定され、中央の操作領域内または操作ボタン上に表示されない。
5. 連打や通知との同時操作でも完了・スキップ記録が重複しない。
6. 完了またはスキップ後に全ウィジェットからTODOが消える。
7. 完了またはスキップ後に確認メッセージや取り消し操作を表示しない。
8. 古いスナップショットから無効なTODOを変更しない。
9. 一時エラーと対象無効を区別して表示更新できる。
10. プロセス終了後も一時エラー状態と最後の正常表示を復元できる。
