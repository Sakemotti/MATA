# ログ・診断データ仕様

- 文書状態: 確定
- 最終更新日: 2026-08-10
- 親仕様: [ログ・診断・品質監視仕様](README.md)

## 1. ログレベル

| レベル | Debug | Release | 用途 |
| --- | --- | --- | --- |
| VERBOSE | 可 | 出力しない | 一時的な詳細追跡 |
| DEBUG | 可 | 出力しない | 分岐、件数、テスト診断 |
| INFO | 可 | 重要な開始・完了だけ | 起動、移行、長時間処理 |
| WARN | 可 | 可 | 縮退、再試行、回復可能障害 |
| ERROR | 可 | 可 | 操作失敗、整合性障害、未分類例外 |

- 正常な行タップ、画面閲覧、文字入力を1件ずつ記録しない。
- 同じエラーの再試行ループでは最初、状態変化、最終結果だけを記録し、ログを連打しない。
- Releaseでスタックトレースを出す場合もメッセージ、Cause、付加データを検査し、禁止情報を含めない。

## 2. 構造

ログは次の固定項目から構成する。

- 固定タグ: `MATA/<component>`
- 固定イベントコード: 例 `DB_MIGRATION_FAILED`
- 結果: `success`、`retry`、`cancelled`、`failure`
- 失敗分類: 共通のエラー型
- 件数または対象範囲
- 単調時計による所要時間
- セッション内だけ有効な処理ID
- Debugビルドでは必要に応じて定義リビジョンやWorker試行回数

- 処理IDはランダムに生成し、ユーザー、端末、TODOを長期間追跡できる値にしない。
- UUID等の永続IDは原則記録せず、必要なDebug診断では一方向のセッション限定別名へ変換する。
- ログ文言を解析してアプリ動作を決めず、イベントコードを定数として管理する。

## 3. 記録禁止項目

- TODOタイトル、説明、カテゴリ名
- 履歴スナップショットと通知本文
- 検索文字列、入力中の下書き
- バックアップ本文、JSON、ZIP内容、ファイル名、完全なURIとパス
- 購入トークン、注文ID、アカウント情報、価格表示以外のBilling応答本文
- 広告ID、端末識別子、IPアドレス、同意文字列、広告応答
- Authorization、Cookie、証明書、APIキー、署名、パスワード
- 完全なIntent、PendingIntent、Bundle、Work入力
- DBの行内容、SQL引数、例外に含まれるユーザー入力
- クリップボード、通知履歴、他アプリ情報

## 4. 許可する診断値

- Build type、versionName、versionCode、OS API
- 端末モデルはDebugの手動診断に限り、Releaseログへ常時記録しない。
- ウィンドウサイズクラス、テーマ、権限の許可・拒否状態
- 固定画面ID、固定繰り返し方式、固定エラー分類
- TODO、カテゴリ、履歴、通知の集計件数
- 日付そのものを含まない処理期間と経過時間
- HTTP状態の分類、応答サイズ、キャッシュヒット、再試行回数
- DBスキーマバージョンと移行元・先バージョン

## 5. 例外

- data層とSDK Adapterで例外を共通失敗型へ変換し、ユーザー向け文言とログを分離する。
- 予期した入力エラー、取消、対象消失をERRORにしない。
- `CancellationException`を障害として記録しない。
- 未分類例外は固定イベントコード、例外型、処理段階だけをERRORへ記録する。
- 外部SDK例外のmessageまたはresponseを無条件にログへ渡さない。
- OutOfMemory時に大きな状態ダンプを作らない。

## 6. 保存と出力

- 通常ログはAndroid Logcatへ出力し、アプリ独自の永続ログファイルを作成しない。
- ユーザー向けの「診断データを送信」機能は初回公開では設けない。
- Clipboard、共有Intent、外部ストレージへログを自動出力しない。
- CIのテストログとベンチマーク結果には合成データだけを使用する。
- CI成果物の保持期間は90日を初期値とし、公開鍵や秘密情報を含まないことを確認する。

## 7. Debug機能

- DebugビルドではStrictMode、テスト用Clock、Fake外部サービス、詳細状態表示を利用できる。
- Debugメニューは`BuildConfig.DEBUG`だけでなくReleaseソースセットと依存関係から除外する。
- Debugログでも記録禁止項目を出力しない。
- テスト広告ID、Fake購入、障害注入をRelease成果物へ含めない。
- 開発中の一時ログはコミット前に削除するか、構造化ログ規則へ移行する。
