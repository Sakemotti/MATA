# バックグラウンド・省電力仕様

- 文書状態: 確定
- 最終更新日: 2026-08-10
- 親仕様: [性能・省電力仕様](README.md)

## 1. 基本方針

- 常駐Foreground Serviceを使用しない。
- 一定間隔の独自Timer、無限Coroutine、分単位ポーリングを使用しない。
- 即時性が不要な永続処理はWorkManagerへ委ねる。
- ユーザーが指定した通知時刻はAlarmManager、遅延可能な整合・取得はWorkManagerと役割を分ける。
- BroadcastReceiverでは処理を完結させず、短い検証と必要なWorkの登録だけを行う。

## 2. 日付境界と一覧更新

- アプリ共通の次の論理日境界だけを予約する。
- 論理日境界を検出するための毎分・毎時ポーリングを行わない。
- フォアグラウンド中はClockと次回境界から必要な時刻に状態を再評価する。
- バックグラウンド復帰時は経過時刻をまとめて整合し、経過した各分を順次再生しない。
- 共通終了時刻、端末時刻、タイムゾーンの変更時は次回境界を再計算し、不要な予約を取り消す。

## 3. 通知

- 実際に必要な将来通知だけを予約し、全無期限予定をAlarmManagerへ展開しない。
- 通知発火後または状態変更後に、対象TODOの次の必要範囲を補充する。
- 正確なアラームが利用できない場合は通知仕様どおり通常アラームへ縮退する。
- 同じTODO、予定、通知設定のアラームを一意なキーで置換し、重複登録しない。
- 再起動、時刻、タイムゾーン、権限変更後の整合処理をまとめ、個別Workerを無制限に作らない。

## 4. WorkManager

- 一意なWork名を使用し、同じ目的の整合処理は`KEEP`または`REPLACE`を仕様に応じて選ぶ。
- 祝日取得はネットワーク接続制約を設定する。
- バッテリー残量低下時やストレージ不足時に必須でない保守処理を開始しない。
- 指数バックオフを使用し、短時間に連続再試行しない。
- Worker入力にはID、バージョン、処理範囲だけを渡し、TODO本文や大容量データを渡さない。
- 10分を超える可能性がある処理は分割・再開可能にし、必要な場合だけ長時間Workerを使用する。

## 5. ウィジェット

- DB変更、論理日境界、通知からの完了、設定変更、復元、OS更新要求を契機に更新する。
- 分単位の定期更新を行わない。
- 複数ウィジェットの同一データを1回のクエリで取得し、表示設定ごとに再利用する。
- 更新要求を短時間に複数受信した場合はまとめ、古いスナップショットで新しい表示を上書きしない。
- 端末がロック中で必要な資格情報ストレージへアクセスできない場合は、解除後の更新へ遅延する。

## 6. 外部通信

- MATAが直接行う業務通信は祝日取得だけとし、広告と同意は各SDKの規則に従う。
- 祝日情報はキャッシュ検証子を使用し、変更がなければ本文を再取得しない。
- アプリ起動のたびに通信せず、キャッシュ期限と次回試行可能時刻を確認する。
- 画面を離れた検索や表示専用通信はキャンセルする。
- Metered Networkでも祝日JSONの取得は許可するが、同じ内容を繰り返し取得しない。
- Data Saver、Doze、App Standbyの制約を回避しない。

## 7. 外部SDK

- 広告はTODO一覧が表示され、同意と権利の条件を満たす場合だけ初期化・読込する。
- UMP、広告、祝日取得をアプリのTTFD条件に含めない。
- SDK初期化をApplication生成時へ無条件に集中させず、依存関係と必要時期を明示する。
- SDKが提供する自動計測やバックグラウンド通信は、プライバシー仕様と公開申告に一致させる。

## 8. 保守処理

- 再生成可能な完了済み通知内部レコードは90日保持後に削除する。
- 一時バックアップ、復元、ダウンロードファイルは処理完了または次回安全起動時に削除する。
- ユーザーのTODO、カテゴリ、履歴、手動バックアップを性能目的で自動削除しない。
- 保守処理は月1回以下を基本とし、前回完了日時を保持する。
- 保守失敗は基本機能を遮断せず、次の適切な契機で再試行する。
