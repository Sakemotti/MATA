# クラッシュ・品質監視仕様

- 文書状態: 確定
- 最終更新日: 2026-08-10
- 親仕様: [ログ・診断・品質監視仕様](README.md)

## 1. Android vitals

- Google Play ConsoleのAndroid vitalsでクラッシュ、ユーザー認識クラッシュ、ANR、起動時間、過度なwake lockを確認する。
- 全体値だけでなく、アプリバージョン、Androidバージョン、端末モデル、国、フォアグラウンド・バックグラウンドを必要に応じて比較する。
- Core vitalの不良動作しきい値超過を公開停止条件とする。
- 新しいリリース期間中は前版との発生率差を確認する。
- 難読化したReleaseの復号に必要なR8 mappingを各versionCodeへ対応付けて保管・アップロードする。

## 2. Pre-launch report

- 内部またはクローズドトラックへAABをアップロードし、Pre-launch reportを本番前に確認する。
- Stability、Performance、Accessibility、Compatibility、Screenshotsを確認する。
- ランチャーActivityからアカウントなしで主要画面へ到達できる状態にする。
- 固定のサンプルデータが必要な検査は専用のテストビルドまたはinstrumented testで行い、実ユーザーデータを使用しない。
- レポートで見つかったクラッシュ、ANR、起動不能、データ破損は修正または明示的な公開判断なしに本番へ進めない。

## 3. クラッシュ報告SDK

- 初回公開では第三者クラッシュ報告SDKを組み込まない。
- Android vitalsだけでは再現不能な重大障害が継続する場合に限り、導入を再検討する。
- 導入時は収集データ、送信先、保持期間、ユーザー制御、難読化、費用を別途仕様化する。
- TODO内容、カテゴリ、履歴、購入トークン、広告IDをBreadcrumb、Custom Key、User IDへ設定しない。
- 導入前にプライバシーポリシー、Data safety、同意要否を更新する。

## 4. 利用分析

- Firebase Analytics、Google Analytics、独自イベント送信を初回公開へ導入しない。
- 画面閲覧、TODO作成・完了、継続率、カテゴリ利用を収集しない。
- Google Playが提供する集計済みインストール、アンインストール、評価、Android vitalsだけを運用品質の判断に使用する。
- 広告SDKが広告提供目的で生成する指標を、TODO利用分析と結合しない。

## 5. 品質トリアージ

| 重大度 | 例 | 初動 |
| --- | --- | --- |
| S0 | データ漏えい、署名鍵侵害、広範なデータ消失 | 公開停止、ロールアウト停止、即時調査 |
| S1 | 起動不能、DB移行失敗、購入権利誤判定、繰り返すANR | 当日中に切り分け、修正版を最優先 |
| S2 | 一部機能クラッシュ、通知誤発火、主要操作不能 | 次回修正版の対象、回避策確認 |
| S3 | 表示崩れ、軽微な性能退行 | 通常優先度で計画 |

- 重大度、影響バージョン、発生開始、再現条件、回避策、修正コミット、公開結果を記録する。
- 個別ユーザーを追跡するIDは記録しない。
- データ消失または履歴改変の疑いは再現率が低くてもS1以上とする。

## 6. 監視頻度

- 新規本番公開と段階公開の各拡大後24時間は、Android vitalsとレビューを毎日確認する。
- 安定後は週1回以上確認する。
- Google Play、Android、主要SDKのポリシー・廃止予定・重大障害を月1回以上確認する。
- 自動通知を設定する場合はクラッシュ率、ANR、公開状態、ポリシー警告に限定し、ユーザーデータを転送しない。
