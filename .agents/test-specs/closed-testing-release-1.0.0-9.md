## 3. 登録前の確認

2026-10-14にクリーンなmainから署名済み候補を生成・保管し、Release事前検査7件と生成元CIが合格した。本番向けGitHubゲートはIssue #299の再確認待ち1件により`failed`のまま保管した。候補の生成はGoogle Playへの配布・実機確認の完了を意味しない。

- クリーンなmainからUpload Key署名済みAABを生成し、単一署名者・証明書・Application ID・versionCode・SHA-256を検証する。
- 生成元mainのCIとCodeQL、Manifest、SBOM、ライセンス、Release事前検査を確認する。
- Issue #299は修正済み・配布後再確認待ちとして保持する。本番向けGitHubゲートで未解決Issueとして残る場合、総合合格へ書き換えず、Closed testing候補の記録へ理由を残す。
- 本候補をProduction向け承認済みとは扱わない。生成・保管だけでGoogle Playへ公開済みと記録しない。
- 更新前のTODO・カテゴリ・履歴・表示設定・通知予定・配置済みウィジェットを確認し、手動バックアップを安全な場所へ保存する。

## 4. Google Play Consoleへの登録

1. 「テストとリリース → テスト → クローズド テスト」から現在運用中の新トラックを開く。
2. 新しいリリースを作成し、検証済みのversionCode `9`のAABをアップロードする。ZIPやmappingをAAB欄へ登録しない。
3. 解析結果が`com.mochisofts.mata`、`1.0.0`、`9`であることと、直前のAABハッシュ照合を確認する。
4. リリース名を`1.0.0 (9) Additional closed testing`とし、第2節の文章を登録する。
5. 新トラックの国・地域、テスター設定と連絡経路を維持する。テスターの再オプトインを求めたり、トラックを作り直したりしない。
6. Consoleのエラー・SDK警告・ポリシー警告を確認する。既知のネイティブデバッグシンボル未登録警告だけであっても、今回の表示と判断を記録する。
7. Closed testingの更新として公開し、公開日時・正確な状態文言・警告を記録する。Productionへ昇格しない。

2026-10-14にUSERが共有したサポート回答では、ダッシュボードの案内カードは初期の標準トラックを参照し、参照先を新トラックへ切り替える機能はない。トラック管理は上記の専用ページを使用する。案内カードを合わせるために旧トラックのテスターを復元しない。
