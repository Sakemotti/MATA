# SCR-004 カテゴリ管理画面仕様

- 文書状態: 確定
- 最終更新日: 2026-08-10
- 関連仕様: [アプリ全体仕様](../../app-spec.md)、[TODO一覧画面仕様](../todo-list/spec.md)、[TODO登録・編集画面仕様](../todo-editor/spec.md)、[カレンダー履歴画面仕様](../calendar-history/spec.md)、[設定画面仕様](../settings/spec.md)

## 1. 目的

TODOを分類するカテゴリの一覧確認、登録、編集、削除、並べ替えを行う画面とする。

カテゴリごとの名前、色、アイコンおよび「一日の終了時刻」を管理し、TODO一覧、TODO登録・編集、論理日、期限、通知へ一貫して反映できるようにする。

## 2. 表示経路と終了経路

### 2.1 カテゴリ一覧の表示経路

- ハンバーガーメニューの「カテゴリ管理」から全画面で表示する。
- カテゴリの追加・編集フォームで保存または破棄して戻った場合は、カテゴリ一覧へ戻る。

### 2.2 カテゴリ追加フォームの表示経路

- カテゴリ一覧の追加ボタンから表示する。
- TODO登録・編集画面のカテゴリ選択ボトムシートにある「新しいカテゴリを作成」から直接表示する。
- TODO登録・編集画面から表示する場合はカテゴリ一覧を経由しない。

### 2.3 カテゴリ編集フォームの表示経路

カテゴリ一覧で、編集可能なカテゴリ行をタップすると表示する。

### 2.4 終了経路

- カテゴリ一覧だけが表示されている場合、システムの戻る操作は主要画面の標準動作に従う。
- 追加・編集フォームで変更がない場合、戻る操作で直ちに呼び出し元へ戻る。
- 追加・編集フォームで未保存の変更がある場合、戻る操作で破棄確認ダイアログを表示する。
- 通常のカテゴリ管理から保存した場合はカテゴリ一覧へ戻る。
- TODO登録・編集画面から追加して保存した場合はTODO登録・編集画面へ戻り、作成したカテゴリを選択状態にする。

## 3. 画面構成

カテゴリ管理機能は次の3つの表示状態で構成する。

1. カテゴリ一覧
2. カテゴリ追加・編集フォーム
3. アイコン選択

カテゴリ追加と編集には共通のフォームを使用する。ダイアログ内でカテゴリ全体を編集しない。

カテゴリ一覧、追加・編集フォーム、アイコン選択のいずれにもバナー広告を表示しない。

## 4. カテゴリ一覧

### 4.1 全体構成

画面上部から次の順に配置する。

1. トップアプリバー
2. 「カテゴリ未設定」行
3. ユーザーカテゴリ一覧
4. 空状態案内。ユーザーカテゴリがない場合のみ表示
5. カテゴリ追加用フローティングボタン

### 4.2 トップアプリバー

- 左側にハンバーガーメニューを表示する。
- 画面タイトルを「カテゴリ管理」とする。
- 一覧全体に対する保存ボタンや編集モード切り替えは設けない。

### 4.3 カテゴリ未設定

「カテゴリ未設定」は、ユーザーが作成するカテゴリとは別の固定区分として一覧の先頭へ常に表示する。

- 並べ替えできない。
- 削除できない。
- 名前、色、アイコンを変更できない。
- 固定色は「グレー」、固定アイコンは「カテゴリ未設定」を表す`CategoryOff`とする。
- 行のタップによる編集を提供しない。
- 操作メニューと並べ替えハンドルを表示しない。
- 一日の終了時刻には、設定画面のアプリ共通値を表示する。
- 終了時刻の下に「設定画面の共通値を使用」と表示する。

### 4.4 ユーザーカテゴリ行

各行に次を表示する。

- カテゴリアイコン
- カテゴリ色
- カテゴリ名
- `一日の終了 4:00`形式の終了時刻
- 並べ替えハンドル
- 操作メニュー

- カテゴリ名は1行で表示する。
- 表示範囲を超える場合は末尾を省略する。
- アクセシビリティサービスには省略しない名前を提供する。
- 色だけでカテゴリを識別させず、名前とアイコンを必ず併記する。
- 行のタップでカテゴリ編集フォームへ移動する。
- 操作メニューには「削除」だけを表示する。

### 4.5 カテゴリの追加

画面右下に`＋`のフローティングボタンを表示する。

- タップするとカテゴリ追加フォームへ移動する。
- 登録可能なカテゴリ数にプロダクト仕様上の上限を設けない。

## 5. 並べ替え

### 5.1 ドラッグ操作

- ユーザーカテゴリ行の右側にある並べ替えハンドルをドラッグして移動する。
- 行全体の長押しでは並べ替えを開始しない。
- 「カテゴリ未設定」は移動対象にも移動先にも含めず、常に先頭へ固定する。
- ドラッグ中の行は影と高さで浮かせて強調する。
- 一覧の上端または下端付近へドラッグした場合は自動スクロールする。
- ドラッグを離した時点で新しい順序を自動保存する。
- 並べ替え専用の保存ボタンは設けない。

### 5.2 アクセシビリティ操作

並べ替えハンドルには、ドラッグ以外に次のカスタムアクセシビリティ操作を提供する。

- 上へ移動
- 下へ移動

先頭のユーザーカテゴリでは「上へ移動」、末尾では「下へ移動」を利用不可にする。移動後は、新しい位置を「3件中2番目」のように読み上げる。

### 5.3 保存と反映

並べ替えの保存中は、追加の並べ替え操作を一時的に無効にする。

保存に成功した場合、次へ即時反映する。

- カテゴリ管理一覧
- TODO一覧のカテゴリタブ
- TODO登録・編集画面のカテゴリ選択
- 同じ期限日時を持つTODOのカテゴリ順による並び替え
- その他カテゴリ順を使用する表示

保存に失敗した場合は、直前に永続化されていた順序へ戻し、一時メッセージで失敗を通知する。

## 6. 追加・編集フォーム

### 6.1 画面タイトル

| モード | 画面タイトル | 保存成功メッセージ |
| --- | --- | --- |
| 追加 | `カテゴリを追加` | `カテゴリを追加しました` |
| 編集 | `カテゴリを編集` | `カテゴリを更新しました` |

### 6.2 トップアプリバー

- 左側に戻るボタンを表示する。
- 右側に文字ボタンの「保存」を表示する。
- 「保存」は、内容が変更済みで、すべての入力が有効な場合だけ有効にする。
- 変更後にすべての値を初期状態へ戻した場合は未変更として扱う。

### 6.3 フォーム構成

画面全体を縦方向にスクロール可能とし、上部から次の順に配置する。

1. カテゴリ行プレビュー
2. カテゴリ名
3. 色
4. アイコン
5. 一日の終了時刻
6. 終了時刻の説明

ソフトウェアキーボード表示中もフォーカス中の入力欄と保存操作が隠れないようにする。

### 6.4 新規作成時の初期値

- カテゴリ名: 空
- 色: 現在のアプリのプライマリカラーに最も近い固定パレット色
- アイコン: 「カテゴリ」
- 一日の終了時刻: 設定画面のアプリ共通値

初期色は作成時に固定パレットの識別子として決定する。保存後にテーマやプライマリカラーが変化しても、保存済みカテゴリの色を変更しない。

- 追加モードではカテゴリ名へ自動フォーカスし、ソフトウェアキーボードを表示する。
- 編集モードでは入力欄へ自動フォーカスせず、ソフトウェアキーボードも自動表示しない。

## 7. カテゴリ行プレビュー

入力中の次の値を組み合わせ、カテゴリ一覧と同等の行プレビューを表示する。

- カテゴリ名
- 色
- アイコン
- 一日の終了時刻

- 入力変更を即時反映する。
- 名前が空の場合は「カテゴリ名」と仮表示する。
- プレビューは確認用であり、タップ操作を持たない。
- エラーがある場合も入力中の値でプレビューを継続する。

## 8. カテゴリ名

### 8.1 入力規則

- 必須の1行入力とする。
- 前後の空白を除去した値を保存する。
- 空白除去後に空文字となる場合は保存できない。
- 最大30文字とする。
- `現在の文字数 / 30`の文字数カウンターを常に表示する。
- 上限を超えた場合は入力欄へエラーを表示し、保存できない。

### 8.2 重複判定

既存カテゴリと同じ名前は登録できない。編集中のカテゴリ自身は比較対象から除外する。

比較用の値には次の正規化を適用する。

1. 前後の空白を除去する。
2. Unicode NFKCで全角・半角などを正規化する。
3. 英字の大文字・小文字を区別しない形式へ変換する。

内部の連続空白は統合せず、入力どおりに扱う。比較用の正規化値とは別に、保存・表示する名前は前後の空白だけを除去したユーザーの入力表記を維持する。

重複時は「同じ名前のカテゴリが既にあります」と表示する。

## 9. 色

### 9.1 選択方法

- 色は必須とする。
- 固定パレットをグリッド形式で表示する。
- 各候補に色見本と日本語名を表示する。
- 選択中の色は枠とチェックマークでも示す。
- 任意色選択、カラーピッカー、カラーコード入力は提供しない。

### 9.2 固定パレット

初期パレットは次の16色とする。保存値には表示名やARGB値ではなく、変更に強い固定の色IDを使用する。

| --- | --- | --- |
| `red` | 赤 | `#C62828` |
| `pink` | ピンク | `#AD1457` |
| `purple` | 紫 | `#6A1B9A` |
| `indigo` | 藍 | `#283593` |
| `blue` | 青 | `#1565C0` |
| `light_blue` | 水色 | `#0277BD` |
| `cyan` | シアン | `#00838F` |
| `teal` | 青緑 | `#00796B` |
| `green` | 緑 | `#2E7D32` |
| `light_green` | 黄緑 | `#558B2F` |
| `lime` | ライム | `#827717` |
| `yellow` | 黄 | `#F9A825` |
| `orange` | オレンジ | `#EF6C00` |

## 10. アイコン

### 10.1 選択方法

- アイコンは必須とする。
- アイコン欄をタップすると、全画面のアイコン選択を表示する。
- アプリ内で用意したMaterial Iconsだけを選択できる。
- 画像アップロード、端末ファイル、絵文字、自由入力には対応しない。
- 選択したアイコンはカテゴリフォームへ戻った時点で即時反映する。

### 10.2 初期候補

初期リリースでは次の候補を用途別グループで提供する。候補追加時も保存済みのアイコンIDを変更しない。

| グループ | 表示名とアイコンID |
| --- | --- |
| 生活 | 家 `Home`、ベッド `Bed`、朝 `WbSunny` |
| 家事 | 掃除 `CleaningServices`、洗濯 `LocalLaundryService`、片付け `DeleteSweep` |
| 買い物 | カート `ShoppingCart`、買い物袋 `ShoppingBag`、店舗 `Storefront` |
| 料理 | 食事 `Restaurant`、キッチン `Kitchen`、料理 `LocalDining` |
| 健康 | ハート `Favorite`、健康管理 `HealthAndSafety`、リラックス `SelfImprovement` |
| 運動 | 筋力トレーニング `FitnessCenter`、ランニング `DirectionsRun`、球技 `SportsSoccer` |
| 医療 | 薬 `Medication`、病院 `MedicalServices`、予防接種 `Vaccines` |
| 勉強 | 学校 `School`、読書 `MenuBook`、ノート `EditNote` |
| 仕事 | 仕事 `Work`、業務 `BusinessCenter`、パソコン `Laptop` |

### 10.3 アイコン検索

アイコン選択の上部に検索欄を表示する。

- 未入力時は用途別グループで候補を表示する。
- 日本語の表示名、グループ名、検索用の日本語キーワードを検索対象とする。
- 大文字・小文字、全角・半角を区別せず検索する。
- 検索中はグループを外し、一致するアイコンだけを一覧表示する。
- 一致しない場合は「該当するアイコンはありません」と表示する。
- 検索欄に検索語を消去するボタンを表示する。
- アイコン候補には表示名を読み上げラベルとして設定する。

## 11. 一日の終了時刻

### 11.1 選択方法

- 必須項目とする。
- 入力欄をタップするとボトムシートを表示する。
- `0:00`から`23:00`まで、1時間単位の24候補から1つを選択する。
- 分単位の指定や時刻の直接入力は提供しない。
- 選択中の時刻を明示する。

### 11.2 説明

入力欄の下に、選択値に応じた論理日の説明を表示する。

- `0:00`: 「カレンダー日と同じ0:00から23:59までを1日として扱います」
- `4:00`: 「4:00の場合、翌日の3:59までを前日分として扱います」
- その他の時刻も同じ規則で動的に表示する。

## 12. 保存とバリデーション

### 12.1 保存前バリデーション

少なくとも次を検証する。

- カテゴリ名が空でなく30文字以内である。
- 正規化後に同名となる別カテゴリが存在しない。
- 固定パレットの有効な色が選択されている。
- 有効なアイコン候補が選択されている。
- 一日の終了時刻が0時から23時の整数である。

入力欄付近に具体的なエラーを表示する。保存操作時にエラーがある場合は最初のエラーへスクロールしてフォーカスし、エラーを読み上げる。

### 12.2 保存処理

- 保存中は「保存」とすべての入力を無効にし、進捗状態を表示する。
- 二重タップによる重複登録や重複更新を防ぐ。
- カテゴリ定義と、それに伴う現在・将来のTODOおよび通知の再計算を一貫した処理として保存する。
- 保存に失敗した場合はフォームに留まり、入力内容を保持して一時メッセージを表示する。
- 編集対象が別処理ですでに削除されている場合は保存せず、「カテゴリが見つかりません」と表示してカテゴリ一覧へ戻る。

### 12.3 保存成功後

通常のカテゴリ管理から保存した場合はカテゴリ一覧へ戻る。

- 新しいカテゴリはユーザーカテゴリの末尾へ追加する。
- 追加後は新しいカテゴリの位置まで自動スクロールする。
- 追加した行を短時間、背景と読み上げ可能なメッセージで強調する。
- 編集後は元のスクロール位置を維持する。
- 「カテゴリを追加しました」または「カテゴリを更新しました」と一時メッセージを表示する。

TODO登録・編集画面から追加した場合はカテゴリ一覧へ移動せず、作成したカテゴリIDを結果として返す。TODO登録・編集画面は下書きを復元し、新しいカテゴリを選択する。

## 13. 変更によるTODOへの影響

### 13.1 名前、色、アイコン

- 現在および将来のTODO表示へ即時反映する。
- 現在進行中の期間に属する完了・スキップ記録の表示用情報へ反映する。
- 期間終了済みの過去履歴は、当時のカテゴリ名、色、アイコンのスナップショットを保持して変更しない。

### 13.2 一日の終了時刻

終了時刻を変更した場合は、次を新しい境界で直ちに再計算する。

- 現在の論理日
- 今日の実行対象
- 未完了の今回分の生成または取り除き
- 実際の期限日時と期限超過状態
- TODO一覧の並び順
- 将来の通知日時と登録状態

- 再計算によって今日が新たに実行対象となった場合は、未完了の今回分を生成する。
- 再計算によって今日が実行対象外となった場合は、未完了の今回分を履歴へ残さず取り除く。
- 完了またはスキップ済みの今回分は保持する。
- 確定済みの過去履歴を再計算しない。
- 時刻経過だけを理由に一覧を定期更新する処理は追加せず、カテゴリ保存を更新契機として再評価する。

### 13.3 無効になる通知

終了時刻の変更により、一日の終了境界より後になるなど無効化される通知が存在する場合は、保存前に確認ダイアログを表示する。

- 影響を受けるTODO件数と通知設定件数を表示する。
- 通知設定自体は削除せず保持することを説明する。
- 無効な通知は発火対象から外れることを説明する。
- 「変更する」でカテゴリ変更を続行する。
- 「キャンセル」でフォームへ戻り、入力内容を維持する。
- 保存後にも「N件の通知設定を確認してください」と一時メッセージで通知する。
- 該当TODOの編集画面では通知へエラーを表示し、修正または削除するまでそのTODOを保存できない。

## 14. カテゴリ削除

### 14.1 削除確認

ユーザーカテゴリ行の操作メニューから「削除」を選択すると確認ダイアログを表示する。

確認ダイアログには次を表示する。

- 削除するカテゴリ名、色、アイコン
- 所属する通常TODOの件数
- 所属するアーカイブ済みTODOの件数
- 所属TODOが「カテゴリ未設定」へ移動すること
- カテゴリ自体は元に戻せないこと
- 再計算により無効になる通知がある場合は、影響を受けるTODO件数と通知設定件数
- 無効な通知設定は保持されるが発火対象外になること

所属TODOが0件の場合も削除確認を表示する。タイトルの再入力は要求しない。

### 14.2 削除処理

- 削除中は対象カテゴリの編集、再削除、並べ替えを無効にして進捗を表示する。
- 通常TODOとアーカイブ済みTODOのカテゴリIDを「カテゴリ未設定」へ変更する。
- 「カテゴリ未設定」のアプリ共通終了時刻で、現在と将来の論理日、期限、今日の実行対象、通知を再計算する。
- 確定済みの過去履歴では、削除前のカテゴリ名、色、アイコンを保持する。
- 無効になった通知設定は削除せず保持し、発火対象から外す。
- カテゴリとTODOの移動を一貫した処理として完了させる。
- 成功後の「元に戻す」は提供しない。

### 14.3 削除後の表示

- カテゴリ管理一覧から対象行を取り除く。
- TODO一覧のカテゴリタブとTODO登録・編集画面の候補から対象カテゴリを取り除く。
- 削除したカテゴリが別画面で選択中だった場合は、「カテゴリ未設定」を含む現在の先頭カテゴリへ切り替える。
- 削除成功を一時メッセージで表示する。
- 無効になった通知がある場合は、その件数も一時メッセージで知らせる。

### 14.4 削除エラー

削除に失敗した場合は、カテゴリ、所属TODO、並び順のいずれも削除前の状態に保ち、一時メッセージで失敗を通知する。

## 15. 未保存内容の破棄

追加・編集フォームでは、トップアプリバーの戻るボタン、システムの戻る操作、ジェスチャーナビゲーションを同じ規則で扱う。

- 変更がない場合は確認せずに呼び出し元へ戻る。
- 変更がある場合は破棄確認ダイアログを表示する。
- 確認文で未保存の変更が失われることを示す。
- 「編集を続ける」でフォームへ戻る。
- 「破棄」で入力内容を破棄して呼び出し元へ戻る。
- ダイアログ外のタップまたは戻る操作では、編集を続ける扱いでダイアログだけを閉じる。

TODO登録・編集画面から表示していた場合、カテゴリ作成を破棄して戻った後もTODOの下書きと元のカテゴリ選択を維持する。

## 16. 状態保持と復元

### 16.1 カテゴリ一覧

画面回転、構成変更、一時的なプロセス再生成では次を復元する。

- スクロール位置
- 追加後の強調対象。強調時間内の場合のみ
- 実行中だった操作の結果確認に必要な状態

通常の新規表示では一覧の先頭から表示する。編集フォームから戻った場合は、仕様に従って元の位置または追加位置を表示する。

### 16.2 追加・編集フォーム

画面回転、構成変更、一時的なプロセス再生成では次を復元する。

- すべての入力値
- 入力エラー
- 未保存の変更状態
- スクロール位置
- アイコン検索語
- アイコン選択画面のスクロール位置

開いていた確認ダイアログ、時刻選択ボトムシートは閉じた状態で復元する。アイコン選択画面を表示中だった場合は、アイコン選択画面と検索状態を復元する。

### 16.3 復元しない場合

- 明示的に破棄した場合は下書きを削除する。
- 保存完了後は下書きを削除する。
- 通常のアプリ終了後に未保存のカテゴリ下書きを復元しない。

## 17. 空、読み込み、エラー状態

### 17.1 空状態

「カテゴリ未設定」以外にユーザーカテゴリが存在しない場合は、固定行の下に次を表示する。

- 「カテゴリを追加してTODOを整理しましょう」
- 「カテゴリを追加」ボタン

空状態内のボタンはフローティングボタンと同じカテゴリ追加フォームを開く。イラストは必須としない。

### 17.2 読み込み状態

- 初回取得に時間がかかる場合は一覧領域に進捗表示を出す。
- 読み込み中に空状態を一時表示しない。
- 追加・編集フォームで既存カテゴリを読み込み中は空のフォームを表示しない。

### 17.3 取得エラー

- 一覧またはフォームにエラーメッセージと「再試行」を表示する。
- 再試行中は重複操作を無効にする。
- フォームで追加候補の色やアイコンを取得できない場合も入力済み内容を保持する。

### 17.4 操作エラー

追加、編集、削除、並べ替えの失敗は画面下部の一時メッセージで通知する。成功していない変更を確定表示せず、入力または直前の永続化状態を維持する。

## 18. アクセシビリティ

- タップ可能領域は原則として48dp以上を確保する。
- アイコンだけのボタンには日本語のアクセシビリティラベルを設定する。
- カテゴリを色やアイコンだけで識別させず、カテゴリ名を併記する。
- 色候補は日本語の色名と選択状態を読み上げ可能にする。
- アイコン候補は日本語の表示名と選択状態を読み上げ可能にする。
- カテゴリ行は、カテゴリ名、アイコン名、一日の終了時刻、一覧内の位置を意味の通る順序で読み上げる。
- 並べ替えハンドルへ「上へ移動」「下へ移動」の代替操作を提供する。
- 移動後の位置、保存結果、削除結果、エラーを読み上げ対象にする。
- 必須項目、入力エラー、保存不可状態を色だけで伝えない。
- フォントサイズを拡大しても、カテゴリ名、終了時刻、保存、並べ替え、削除の主要操作が欠けないようにする。

## 19. 受け入れ条件

1. ハンバーガーメニューからカテゴリ管理一覧を全画面で表示できる。
2. 「カテゴリ未設定」を先頭へ固定し、編集、削除、並べ替えできないようにできる。
3. ユーザーカテゴリ行へアイコン、色、名前、終了時刻、並べ替え、削除操作を表示できる。
4. カテゴリ名を1行に制限し、省略時も支援技術へ全文を提供できる。
5. フローティングボタンと空状態からカテゴリ追加フォームを開ける。
6. カテゴリ行のタップでカテゴリ編集フォームを開ける。
7. ユーザーカテゴリだけをドラッグで並べ替え、ドロップ時に自動保存できる。
8. 一覧端へのドラッグで自動スクロールできる。
9. 支援技術から「上へ移動」「下へ移動」で並べ替えられる。
10. 並べ替えをカテゴリタブ、カテゴリ選択、TODOの同期限時の並び順へ反映できる。
11. 追加・編集フォームにプレビューと4項目を仕様どおりの順で表示できる。
12. カテゴリ名の必須、30文字、正規化後の重複を検証できる。
13. 保存するカテゴリ名では、前後の空白だけを除去してユーザー表記を維持できる。
14. 16色の固定パレットを名前とチェック状態付きで選択できる。
15. 保存後のカテゴリ色がテーマ変更によって変化しない。
16. 用途別のMaterial Icons候補を表示し、日本語で検索できる。
17. アイコン検索結果がない状態と検索語の消去操作を提供できる。
18. 0:00から23:00までの終了時刻を1時間単位で選択できる。
19. 選択した終了時刻に応じた論理日の説明を表示できる。
20. 有効かつ変更済みの場合だけ保存でき、保存中の二重操作を防止できる。
21. 通常の追加後は一覧の新しい行へ移動して強調し、編集後は一覧位置を維持できる。
22. TODO登録・編集画面から追加した場合、TODOの下書きを維持して新しいカテゴリを選択できる。
23. 名前、色、アイコンの変更を現在と将来へ反映し、確定済みの過去履歴を変更しない。
24. 終了時刻の変更後に現在と将来の論理日、期限、予定、通知を再計算できる。
25. 再計算で実行対象外となる未完了の今回分を履歴なしで取り除き、完了・スキップ済み記録を保持できる。
26. 無効になる通知件数を変更前に確認し、設定を保持したまま発火対象から外せる。
27. 削除確認に通常TODO、アーカイブ済みTODO、無効になる通知の件数と影響を表示できる。
28. カテゴリ削除時に所属TODOを「カテゴリ未設定」へ移し、過去履歴のカテゴリ情報を維持できる。
29. 削除したカテゴリが選択中の場合、現在の先頭カテゴリへ切り替えられる。
30. 削除後の元に戻すを提供しない。
31. 未保存の変更がある場合だけ破棄確認を表示できる。
32. 画面回転や一時的なプロセス再生成後に一覧位置、フォーム入力、検索状態を復元できる。
33. 空、読み込み、取得エラー、操作エラーを区別して表示できる。
34. TalkBackなどの支援技術でカテゴリ情報、選択状態、並べ替え、エラー、主要操作を識別できる。
35. カテゴリ管理一覧と追加・編集フォームにバナー広告を表示しない。

## 20. 未決定事項

本画面の実装に必要なプロダクト仕様上の未決定事項はない。

固定パレットのテーマ別表示トーン、検索用キーワードの具体的な辞書、ドラッグ中のアニメーション値は、本文書の要件を満たす範囲で実装設計時に決定する。
