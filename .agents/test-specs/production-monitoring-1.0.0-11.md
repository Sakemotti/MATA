## 2. MON-20261104-01 カテゴリ並べ替え

- [カテゴリ管理仕様第5節](../screen-specs/category-management/spec.md#5-並べ替え)で必要な機能であり、未提供の仕様ではない。

- 調査開始時のmainは`b670e87e307891dc7c11474869c6973419d50945`。カテゴリ画面・ViewModelのコードは公開タグ`v1.0.0`と差分なし。
- 読み取り専用・ヘッドレスのAPI 34 x86_64 AVDに、偽Repositoryと2カテゴリを使う一時的な実タッチ試験を追加。ハンドルを押下し、800ms保持、描画更新を挟んで12回移動し、指を離した。
- 修正前は期待順序`[game, daily]`に対して実際は`[daily, game]`で失敗。固定文字列だけの一時ログで、`drag-start`の約25ms後に`drag-cancel`が発生し、移動・保存へ進めないことを確認した。
- この再現はmainのDebug構成であり、保管済み公開AAB自体の再実行ではない。実機での発生報告と、開発側の再現結果を区別する。

### 原因と修正

1. ドラッグ開始の描画更新で親行のホバー用入力ノードを外し、クリック入力も無効化していた。進行中の子ハンドルのジェスチャーがキャンセルされたため、親の入力ノードは維持し、ドラッグ中の行タップはクリック処理内で抑止する。
2. 上記を防いだ比較試験では開始・移動・終了まで進んだが、移動ごとに入れ替えが繰り返され、最終順序が戻った。ドラッグ対象を除いた表示行の端を無条件に移動先とする判定をやめ、移動方向にある相手行の中央を越えた場合だけ入れ替える。
3. 既存の`CM-007`はViewModel呼び出し、`CM-008`は`CategoryDragTestController`経由であり、ハンドルの実タッチ入力と描画更新を通していなかった。保存ロジック等の既存試験に加え、実タッチの下移動・上移動・キャンセル、および中央境界の単体試験を追加する。

実装は[カテゴリ画面](../../app/src/main/java/com/mochisofts/mata/ui/category/CategoryScreens.kt)、回帰試験は[Compose UI試験](../../app/src/androidTest/java/com/mochisofts/mata/ui/category/CategoryManagementScreenSpecCoverageTest.kt)と[単体試験](../../app/src/test/java/com/mochisofts/mata/ui/category/CategoryListViewModelTest.kt)を参照する。診断用ログは削除し、ユーザー入力・カテゴリ名を診断ログへ出さない。
