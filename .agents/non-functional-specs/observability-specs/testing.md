# ログ・診断・品質監視の検証仕様

- 文書状態: 確定
- 最終更新日: 2026-08-10
- 親仕様: [ログ・診断・品質監視仕様](README.md)

## 1. ログ検査

- TODOタイトル、説明、カテゴリ、検索語へ一意な検査文字列を設定する。
- 通知、バックアップ、復元、祝日、広告の成功・失敗を実行する。
- Logcat、テスト出力、CI成果物、例外、WorkManager診断へ検査文字列が出ないことを確認する。
- トークン、注文ID、URI、絶対パス、Intent全体、HTTP本文が出ないことを確認する。
- 同じ再試行を連続発生させ、ログ件数が無制限に増えないことを確認する。

## 2. Build type検査

- Debugで必要な構造化ログ、StrictMode、Fake、障害注入を利用できる。
- ReleaseでVERBOSEとDEBUGが出力されない。
- Release成果物にDebugメニュー、テスト用Activity、Fake、テスト広告ID、開発URLが含まれない。
- Releaseで未分類例外を安全な固定項目だけで記録できる。
- DebugとReleaseのどちらでも禁止項目が出力されない。

## 3. 難読化とPlay検査

- 各ReleaseのmappingをversionCodeと対応付けて保管する。
- 人工的なテストクラッシュで難読化スタックを復号できる。
- 内部・クローズドトラックのPre-launch reportを生成し、全セクションを確認する。
- Android vitalsでReleaseバージョンを識別できる。
- 公開後の監視頻度と重大度別初動を実行記録へ残す。

## 4. プライバシー検査

- Firebase Crashlytics、Analyticsその他の未承認監視SDKが依存関係とManifestにない。
- ネットワーク検査で独自ログ・分析エンドポイントへの送信がない。
- 広告とUMP通信をMATA独自のログと区別できる。
- Google Play Data safetyとプライバシーポリシーに監視方針が一致する。

## 5. 受け入れ条件

1. DebugとReleaseで定義済みログレベルを使い分けられる。
2. ログを固定イベントコード、結果、分類、件数、所要時間で記録できる。
3. TODO内容、検索語、通知本文、バックアップ内容をログへ記録しない。
4. 広告、認証、URI、Intentの機密値をログへ記録しない。
5. 再試行ループで同じログを無制限に出力しない。
6. Release成果物からDebug診断機能とテスト設定を除外できる。
7. 第三者クラッシュSDKと利用分析SDKを初回公開へ含めない。
8. Android vitalsとPre-launch reportでクラッシュ、ANR、性能、アクセシビリティを確認できる。
9. R8 mappingを各versionCodeへ対応付け、スタックを復号できる。
10. S0～S3の重大度で障害を分類し、公開停止条件を判断できる。
11. 公開直後と安定後の監視記録を残せる。
12. ログ・診断の実装がプライバシーポリシーとData safetyに一致する。
