# MATA 手動バックアップ形式バージョン2

- 文書状態: 確定
- 最終更新日: 2026-08-25
- 基底仕様: [バックアップ形式バージョン1](format-v1.md)

## 1. 適用範囲

バージョン2は、バージョン1のZIP構造、文字コード、正規順序、件数、ハッシュ、入力上限および参照整合性を継承し、繰り返し設定の期間週数と対象日条件を追加する現行書き出し形式である。

- `manifest.json.formatVersion`: `2`
- `manifest.json.minimumReaderVersion`: `2`
- `data.json.formatVersion`: `2`
- 読み込み側はバージョン1と2を受け付け、バージョン1を端末内の現行モデルへ変換する。
- バージョン1の週X回は、期間週数1、対象日条件「すべての日」として復元する。
- バージョン1の曜日指定は、祝日条件を持たない任意曜日指定として復元する。

## 2. 対象日条件コード

`dayFilter`は次の固定コードだけを受け付ける。

| コード | 意味 |
| --- | --- |
| `all` | すべての日。N週間にX回だけで使用できる |
| `weekdays` | 月曜日から金曜日のうち日本の祝日ではない日 |
| `weekends_holidays` | 土曜日、日曜日および曜日を問わない日本の祝日 |
| `custom` | `weekdays`配列で指定した曜日。祝日による追加・除外なし |

未知コード、曜日指定の`all`、空の`custom`、重複または未整列の曜日配列は復元前検証で拒否する。

## 3. TODOのrepeatParams

バージョン1から変更のない繰り返し方式は、同じフィールドと意味を維持する。

### 3.1 曜日指定

フィールド順は次とする。

1. `dayFilter`: string。`weekdays`、`weekends_holidays`または`custom`
2. `weekdays`: string array。月曜日から日曜日の昇順。プリセットでは対応曜日、`custom`では1件以上

### 3.2 N週間にX回

フィールド順は次とする。

1. `periodWeeks`: integer。1～52
2. `requiredCount`: integer。1～`periodWeeks × 7`
3. `dayFilter`: string。4種類の対象日条件コード
4. `weekdays`: string array。`custom`では1件以上、その他ではプリセットに対応する配列または空配列

## 4. 復元と再構築

- 復元後は期間境界、現在の進捗、一覧、通知およびウィジェットを復元時点の週開始曜日と祝日キャッシュから再計算する。
- 確定済み履歴のスナップショットは書き換えない。
- バックアップへ祝日キャッシュを含めないというバージョン1の原則を維持する。

## 5. 受け入れ条件

1. バージョン2で期間週数、必要回数、対象日条件および任意曜日を欠落なく往復できる。
2. バージョン1の曜日指定と週X回を既定値で復元できる。
3. バージョン2をバージョン1だけに対応する読込実装へ誤って受け入れさせない。
4. 不正な対象日条件、範囲外の期間週数・必要回数、重複曜日をデータ変更前に拒否できる。
