# 画面別適応レイアウト仕様

- 文書状態: 確定
- 最終更新日: 2026-08-10
- 親仕様: [画面サイズ・適応レイアウト仕様](README.md)

## 1. 共通ルール

- 既存の画面ID、画面遷移、表示条件、並び順、操作および受け入れ条件は各画面仕様を正とする。
- サイズ変更は情報量を削る理由にせず、配置、最大幅、ペイン構成だけを変える。
- CompactとMediumで別画面として表示する詳細は、Expanded以上の2ペインでは右ペインへ表示してよい。
- 2ペイン表示でも詳細の戻る階層を保持し、単一ペインへ縮小した際に同じ詳細を継続表示する。
- 画面幅が広くても、TODOカードや設定項目を複数列のグリッドにしない。

## 2. TODO一覧

- 全サイズで日付操作とカテゴリ区切り付きの単一リストを維持する。
- TODOを複数列またはカードグリッドへ変更しない。
- コンテンツの最大幅は840dpとし、中央配置する。
- 日付移動、日付選択、完了済み表示切り替えの機能を全サイズで維持する。
- カテゴリ区切り行と所属TODOの関係が横幅によって不明瞭にならないようにする。
- フローティングボタンはコンテンツ右下に配置し、ナビゲーション、広告、Snackbar、IME、システムInsetsと重ねない。
- 読み取り専用TODO詳細は共通ダイアログ幅に従う。

## 3. カテゴリ別TODO一覧

- 全サイズでカテゴリタブと単一列のTODO一覧を維持する。
- コンテンツの最大幅は840dpとし、中央配置する。
- 横幅不足時はカテゴリタブを横スクロール可能とする。
- TODO行を複数列またはカードグリッドへ変更しない。

## 4. TODO登録・編集

- 全サイズで単一列フォームとし、最大幅720dpで中央配置する。
- セクション、入力項目および保存操作の順序を変更しない。
- 日付・時刻・繰り返しの選択ダイアログは最大560dpとする。
- カテゴリ選択ボトムシートは最大640dpとし、広い画面でも画面全幅へ引き伸ばさない。
- 高さCompactまたはIME表示中はフォームを縦スクロール可能にし、フォーカス中の入力欄とエラーを表示領域へ移動する。
- 保存・破棄・アーカイブ・削除の操作は、横幅やIMEにより到達不能にしない。

## 5. カレンダー履歴

### 5.1 Compact / Mediumまたは2ペイン条件未達

- 月カレンダーの下に選択日の履歴領域を縦方向へ配置する。
- 画面全体を縦スクロールし、月操作と選択日を失わない。

### 5.2 Expanded以上の2ペイン

- 左ペインへ月カレンダー、右ペインへ選択日の概要と履歴を表示する。
- 左ペイン幅は最小360dp、最大480dpとする。
- 右ペイン幅は最小352dpとし、残りの幅を使用する。
- ペイン全体の最大幅は1200dpとし、中央配置する。
- 日付選択は右ペインだけを更新し、画面全体の再生成やスクロールリセットを行わない。
- 履歴詳細ダイアログと完了取り消し確認は、選択した履歴が属するペインを基準に表示する。

## 6. カテゴリ管理

### 6.1 Compact / Mediumまたは2ペイン条件未達

- カテゴリ一覧、追加・編集フォーム、アイコン選択は画面仕様どおり別の表示階層とする。

### 6.2 Expanded以上の2ペイン

- 左ペインへカテゴリ一覧、右ペインへ追加・編集フォームを表示する。
- 左ペイン幅は最小320dp、最大400dpとする。
- 右ペイン幅は最小392dpとし、残りの幅を使用する。
- 初期状態では右ペインに「カテゴリを選択するか、新しいカテゴリを追加してください」と表示する。
- 選択中のカテゴリを左ペインで明示し、保存後も選択を維持する。
- 削除後は選択を解除し、右ペインを初期状態へ戻す。
- アイコン選択は既存の独立した表示階層を維持し、最大幅840dpで中央配置する。
- ドラッグ中のサイズ変更では安全に並べ替えを中止し、確定済みの順序を保持する。

## 7. アーカイブ済みTODO一覧

### 7.1 Compact / Mediumまたは2ペイン条件未達

- 一覧と詳細を別の表示階層とする。

### 7.2 Expanded以上の2ペイン

- 左ペインへ検索とアーカイブ一覧、右ペインへ選択したTODOの詳細と履歴を表示する。
- 左ペイン幅は最小320dp、最大400dpとする。
- 右ペイン幅は最小392dpとし、残りの幅を使用する。
- 初期状態では右ペインに「TODOを選択してください」と表示する。
- 復元または完全削除後は選択を解除し、一覧を再評価する。
- 検索条件変更で選択対象が一覧から外れた場合は選択を解除する。

## 8. 設定

- 全サイズで単一列とし、最大幅720dpで中央配置する。
- 設定セクションを複数列へ分割しない。
- 長時間処理中の進捗、確認ダイアログ、Storage Access Frameworkからの復帰状態をサイズ変更後も維持する。

## 9. 共通オーバーレイ

| UI | 最大幅 | 補足 |
| --- | --- | --- |
| AlertDialog | 560dp | セーフエリア内で高さを制限し、本文をスクロール可能にする |
| Modal Bottom Sheet | 640dp | 広い画面では中央寄せし、ヒンジをまたがない |
| Popup / Dropdown | 320dp | アンカーと同一の安全領域へ収める |
| Snackbar | コンテンツ幅 | ナビゲーション、広告、FAB、IMEより上へ表示する |

- 日付選択や時間選択は利用可能な安定版Materialコンポーネントを使用する。
- ダイアログとシートを表示中にサイズが変わっても、入力内容と表示状態を保持する。
- オーバーレイが新しい安全領域へ収まらない場合は、閉じずに位置とサイズを再計算する。

## 10. バナー広告

- TODO一覧およびカテゴリ別TODO一覧のコンテンツ領域内で最大840dpに制限し、中央配置する。
- ナビゲーション領域を含むウィンドウ全幅を広告幅として渡さない。
- 幅、方向、分割画面または折り目が変わった場合は利用可能な広告幅を再計算する。
- 幅の変化が300ms安定した後に必要なバナーサイズを確定する。
- 同じサイズへの重複読み込みを行わず、旧サイズの広告を破棄してから新しいサイズを読み込む。
- 初回読み込み中は現在の利用可能幅から算出した高さを確保し、読み込み成功時に高さを変更しない。
- 幅の再計算中は直前の高さを維持し、読み込み失敗時は空の広告領域を残さない。
- 広告の出現・消失で選択、スクロール位置、完了操作、Snackbarを失わない。
