## 1. 目的と現在位置

versionCode `2`から`3`へのGoogle Play上書き更新は、Pixel 9a（Android 17 / API 37）で問題がないことを2026年9月9日にUSERが確認した。アプリ起動、既存データ、設定、通知、ウィジェットおよびバックアップ機能は維持された。同日、versionCode 3固有の実機確認9項目と、本書で定めた環境別7セッションもすべて合格した。

本書では、上書き更新の成功だけでは判定できないversionCode 3固有の変更と、初回リリースに不足しているOS・画面形態・アクセシビリティ条件だけを抽出する。全420項目を再掲せず、各試験IDの完全な合格条件はリンク先の項目書を正とする。

#### V3-01 カテゴリ色と入力欄

1. カテゴリ管理の追加・編集フォームで16色を順に選ぶ。
2. 選択色がカテゴリ名の入力枠へ即時反映され、文字色はテーマ標準のままであることをライト・ダーク双方で確認する。
3. カテゴリ名を入力エラーにし、エラー色とメッセージがカテゴリ色より優先されることを確認する。
4. TODO編集でカテゴリ未設定と16色のカテゴリを順に選び、対象入力枠へ色が反映されることを確認する。
5. TODO編集でも入力エラー表示がカテゴリ色より優先されることを確認する。

合格対象は[カテゴリ管理`CM-032`](category-management.md)と[TODO編集`TE-034`](todo-editor.md)である。

#### V3-02 単発TODOの実行日・期限日

1. `QA-V3-期限`を単発TODOとして作成し、実行日を今日、期限日を2日後にする。
2. 保存・再編集後も両日が維持されることを確認する。
3. 実行日、翌日、期限日の一覧に同じ1回分が表示され、日ごとに複製されないことを確認する。
4. 期限日と期限時刻の表示、期限順の並び、期限超過前後の表示を確認する。
5. 期限日未設定と実行日同日の保存を確認し、実行日より前の期限日が拒否されることを確認する。
6. 繰り返しTODOでは期限日の入力が表示・保存されないことを確認する。

合格対象は[TODO編集`TE-035`](todo-editor.md)と[TODO一覧`TL-035`](todo-list.md)である。

#### V3-03 未完了繰り越しとウィジェット

1. 日付固定型の`QA-V3-繰越ON`と`QA-V3-繰越OFF`を作り、前者だけ繰り越しを有効にする。
2. 回数指定型では繰り越し設定が表示・保存されないことを確認する。
3. 専用カテゴリの一日の終了時刻を、確認可能な次の境界へ設定する。
4. 両TODOを未操作のまま論理日境界を越え、OFFは一覧から消え、ONだけが元の実行日を維持して表示されることを確認する。
5. ONが一覧とウィジェットに1件だけ表示され、元の実行日、期限、繰り越しまたは期限超過を識別できることを確認する。
6. ウィジェットから完了し、一覧とウィジェットの双方から消えることを確認する。別データでスキップも同様に確認する。

合格対象は[TODO編集`TE-036`](todo-editor.md)、[TODO一覧`TL-035`](todo-list.md)、[ウィジェット`WGT-015`](app-core.md)である。論理日境界を実際に越えていない場合は合格にしない。

#### V3-04 過去詳細からの編集・完全削除

1. 現在も有効な繰り返しTODOに過去日の完了またはスキップ履歴を作る。
2. カレンダー履歴または過去日のTODO詳細から「編集」を開き、現在のタイトル・カテゴリ・予定を変更する。
3. 現在と将来だけが更新され、過去履歴のタイトル、カテゴリ、実行日、解決日およびスナップショットが変わらないことを確認する。
4. `B3`を作成後、別の`QA-V3-削除`を過去詳細から完全削除する。
5. 日単位削除が提供されず、確認を取り消せば残り、確定時だけTODO、全履歴、期間結果、通知および現在状態が削除されることを確認する。
6. 完全削除を元に戻せないことを確認する。

合格対象は[TODO一覧`TL-033`・`TL-034`](todo-list.md)と[TODO編集`TE-037`](todo-editor.md)である。

### 3.1 共通準備と記録

1. Google Play版versionCode `3`または同じソースから生成したRelease相当版を使う。
2. 実機では既存バックアップ`B0`・`B3`を保持し、破壊的な時計変更は専用エミュレータで行う。
3. エミュレータは各セッション開始前にデータを初期化し、API、画面サイズ、向き、MATAのversionCodeを記録する。
4. `QA-ENV-`で始まるカテゴリ、単発TODO、毎日TODOを用意し、期限時刻と通知は確認中に到来する将来時刻へ設定する。
5. 各セッションについて、実施日、端末またはAVD名、Android/API、結果、不具合Issueを第4節へ記録する。

### 3.2 `ENV-26` 最小対応OS

推奨環境はAPI 26のスマートフォンAVDである。

1. MATAを新規インストールして起動し、TODO一覧が操作可能になることを確認する。
2. カテゴリを作成し、単発TODOと毎日TODOを1件ずつ登録する。
3. TODOの完了とスキップを行い、カレンダー履歴へ正しい状態が表示されることを確認する。
4. 一日の終了時刻、週の開始曜日、テーマを変更し、アプリを終了・再起動して値が維持されることを確認する。
5. ハンバーガーメニューから全主要画面を1回ずつ開く。

`APP-001`の合格条件は、インストール・起動・主要操作に成功し、クラッシュ、ANR、操作不能、保存消失がないことである。

### 3.3 `ENV-33` 通知権限

推奨環境はAPI 33のスマートフォンAVDである。通知到着確認中は端末時刻を変更しない。

1. アプリデータを初期化して起動し、通知権限を拒否する。
2. 数分後に通知予定のTODOを保存し、TODOと通知設定は保存される一方、通知が表示されないことを確認する。
3. 通知予定時刻の経過後にOS設定から通知権限を許可し、経過済み通知が遅れて表示されないことを確認する。
4. 新しい将来通知を設定し、予定時刻に1回だけ届くことを確認する。
5. OS設定で「アラームとリマインダー」を不許可にし、MATAでフォールバック案内を確認してから将来通知が届くことを確認する。
6. 設定を許可へ戻し、将来通知が重複しないことを確認する。

`NTF-003`、`NTF-006`〜`NTF-008`の合格条件は、拒否中もTODOを失わず、許可後は将来分だけが登録され、経過済み・重複通知がなく、正確なアラーム不可時に案内とフォールバックが機能することである。

### 3.4 `ENV-36` targetSdk相当OS

推奨環境はAPI 36のスマートフォンAVDである。

1. 新規インストール後に通知権限を許可し、TODO・カテゴリの登録、編集、完了、スキップ、アーカイブ、復元、完全削除を各1回行う。
2. TODO一覧、カテゴリ別一覧、TODO編集、カレンダー、カテゴリ管理、アーカイブ、設定を順に開く。
3. 将来通知を1件受信し、ホーム画面へウィジェットを追加して完了またはスキップを1件行う。
4. TODO編集、カレンダー、設定を表示したまま縦横を切り替え、保存済みデータと選択状態を確認する。

合格条件は、API 36固有の権限・画面制約下でも主要機能を操作でき、クラッシュ、ANR、データ欠損、通知重複、ウィジェット不整合がないことである。

### 3.5 `ENV-LARGE` 広画面・分割画面

推奨環境は最小幅600dp以上のタブレットまたはResizable AVDである。

1. 縦向きと横向きで全主要画面を開き、ナビゲーション、一覧、詳細、FAB、広告、固定ボタンが画面外へ欠けないことを確認する。
2. カテゴリ別一覧とカレンダーでカテゴリ・日付を選び、回転および幅変更後も選択と表示内容が一致することを確認する。
3. TODO編集とカテゴリ編集でキーボードを表示し、末尾の入力項目と保存操作までスクロールできることを確認する。
4. Androidの分割画面でMATAの幅を変更し、狭い状態と600dp以上の状態を往復する。
5. 2ペイン表示になる画面では、左右の選択関係が崩れず、同じ内容が重複表示されないことを確認する。

`CTL-010`を含む合格条件は、リサイズ後も選択を保持し、主要操作がシステム領域、IME、分割境界と重ならず利用できることである。

### 3.6 `ENV-VISUAL` テーマ・表示倍率

[REL-008専用手順](rel-008-visual-check.md)を正として、Pixel 9aで次の4条件を実施する。

- ライト・標準フォント・標準表示サイズ
- ダーク・標準フォント・標準表示サイズ
- ライト・最大フォント・最大表示サイズ
- ダーク・最大フォント・最大表示サイズ

各条件で主要11画面を確認し、最後にテーマを「端末設定に従う」としてライト・ダークを切り替える。文字や操作の欠け、致命的な重なり、読めない状態、末尾へ到達できない画面がなければ`REL-008`を合格とする。

### 3.7 `ENV-TALKBACK` アクセシビリティ

Pixel 9aでTalkBackを有効にし、次を確認する。

1. TODO一覧から編集、カテゴリ管理、カレンダー、アーカイブ、設定の順にスワイプ移動する。
2. 戻る、保存、完了、スキップ、日付移動、タブ、チェック状態について、役割と現在状態が読み上げられることを確認する。
3. 入力エラーと文字数超過がフォーカス移動だけで認識できることを確認する。
4. 削除、完全削除、復元などの確認画面で、対象と影響、実行・キャンセルを区別できることを確認する。
5. カテゴリ色、完了、スキップ、期限超過が色だけに依存せず文言または状態として判別できることを確認する。

`TL-025`、`TE-030`、`CM-030`、`CH-034`、`AT-039`、`ST-044`、`CTL-010`の合格条件は、読み上げ順が操作順と一致し、無名操作やフォーカス不能な主要操作がないことである。

### 3.8 `ENV-RECOVERY` 障害・再生成

時計とタイムゾーンの変更は、実データへの影響を避けるため専用エミュレータを推奨する。

1. 既存TODO、履歴、設定、将来通知、ウィジェットを用意して機内モードにし、TODO・カテゴリ・履歴・設定を操作する。
2. オンラインへ戻し、端末内データが変化せず、広告等の外部通信失敗で強制終了しないことを確認する。
3. 編集途中や設定の選択途中でアプリをバックグラウンドへ移し、`adb shell am kill com.mochisofts.mata`後に再度開く。保存済みデータを失わず、処理を二重実行しないことを確認する。
4. 将来通知とウィジェットを用意して端末を再起動し、起動後の一覧・通知・ウィジェットが一致することを確認する。
5. 専用エミュレータでタイムゾーンを変更してMATAを開き直し、将来通知が新しい実日時へ移り、経過済み通知や重複通知が出ないことを確認する。
6. 端末時刻、タイムゾーン、ネットワーク、権限、テーマ、フォントを元へ戻す。

`APP-005`、`DAY-011`、`NTF-011`、`ST-028`、`ST-043`の合格条件は、オフライン・再生成・再起動・時刻環境変更後も確定済み履歴を変えず、保存済みデータを失わず、将来通知とウィジェットを重複なく再構成することである。

### 3.9 共通合格条件

- クラッシュ、ANR、データ欠損および操作不能がない。
- 主要操作が画面外へ欠けず、システムバー、IME、ヒンジまたは分割境界と重ならない。
- 回転・再生成後に永続データを失わず、一時状態は各画面仕様どおり復元または安全に閉じる。
- TalkBackでは情報、状態、選択、操作名、エラーおよび破壊的影響を色だけに依存せず識別できる。
- 通知・時計条件では経過済み通知や重複通知を発火せず、将来分を再計算する。
- 実施できなかった条件を類似環境から推測して合格にしない。
