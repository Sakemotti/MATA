# 性能計測・公開判定仕様

- 文書状態: 確定
- 最終更新日: 2026-08-10
- 親仕様: [性能・省電力仕様](README.md)

## 1. 基準データ

| データ | 標準 | 大量 |
| --- | --- | --- |
| 通常TODO | 100件 | 10,000件 |
| アーカイブTODO | 100件 | 10,000件 |
| カテゴリ | 20件 | 200件 |
| 日単位履歴 | 10,000件 | 1,000,000件 |
| 期間結果 | 1,000件 | 100,000件 |
| TODOごとの通知 | 0～3件 | 上限10件を混在 |

- 大量データは無期限、各繰り返し方式、カテゴリなし、異なる終了時刻を含める。
- 同じSeedから再生成可能にし、計測ごとにデータ分布を変えない。
- 端末の現在時刻、タイムゾーン、表示月を固定できるようにする。

## 2. 基準端末とビルド

- minSdk付近の低性能側端末または同等の管理された物理端末を基準端末とする。
- 現行の代表端末と大画面端末を比較端末とする。
- Release相当、R8有効、Baseline Profile適用、Debuggable無効で公開判定する。
- 充電状態、温度、バックグラウンド負荷、OS、ビルドを記録する。
- エミュレーターの絶対時間だけで公開判定しない。

## 3. Macrobenchmark

- Cold、Warm、Hot起動は起動仕様に従う。
- TODO一覧初回表示、日付移動、カテゴリ区切り付き一覧の完了・スクロール、およびカテゴリ別TODO一覧のカテゴリ切替を計測する。
- カレンダー表示、月移動、履歴スクロールを計測する。
- アーカイブ検索、詳細表示、ページ追加取得を計測する。
- 大画面のサイズクラス変更と2ペイン切替を計測する。
- FrameTiming、起動時間、アプリ処理区間を保存し、CI成果物として比較可能にする。

## 4. Microbenchmarkと単体計測

- 論理日計算、全繰り返し方式、次回予定、週・月期間集計を計測する。
- Roomの主要クエリ、ページ取得、月集計、移行を標準・大量データで計測する。
- バックアップ作成、検証、復元を代表サイズで計測する。
- 通知整合、ウィジェットスナップショット生成、祝日再計算を計測する。
- ベンチマーク対象からテストデータ生成と初回ウォームアップを除外する。

## 5. メモリ・電力・ネットワーク

- Android Studio ProfilerまたはPerfettoで一覧、カレンダー、バックアップ、復元のメモリを確認する。
- 画面往復と回転を繰り返し、Activity、ViewModel、広告、Cursor、Coroutineのリークを確認する。
- Background Task Inspector、Battery Historianまたは同等の手段でWorkとAlarmの頻度を確認する。
- 24時間の通常利用で分・時単位の不要な起床やネットワークポーリングがないことを確認する。
- オフラインと不安定回線で再試行が無限に増えないことを確認する。

## 6. 回帰判定

- 前回公開版または承認済み基準と同じ端末・データで比較する。
- 主要指標の中央値が20%以上悪化した場合は原因と影響を確認し、承認なしで公開しない。
- クラッシュ、ANR、OutOfMemory、データ不整合は平均値に関係なく公開不可とする。
- 単発の外れ値を除外する規則と試行回数を計測前に固定する。
- 改善値だけを選ばず、中央値、p95、分布、試行数を保存する。

## 7. 受け入れ条件

1. 主要操作で100ms以内に視覚応答を開始できる。
2. 標準データで端末内の主要表示・更新が定義済み目標を満たす。
3. 大量データでクラッシュ、ANR、OutOfMemoryを発生させず全件へ到達できる。
4. TODO一覧、カレンダー、アーカイブで全履歴を一括読込しない。
5. 主要クエリにN+1がなく、クエリプランとインデックスを検証できる。
6. メインスレッドのネットワーク、DB、ファイルI/OをStrictModeで検出し解消できる。
7. 無期限TODOを無限展開せず、通知とウィジェットを必要範囲だけ計算できる。
8. 分・時単位の不要なポーリングと常駐サービスがない。
9. Work、Alarm、ウィジェット更新を重複登録しない。
10. バックアップと復元をストリーミングし、代表サイズで完了できる。
11. 主要フローのMacrobenchmarkと業務計算のMicrobenchmarkを再現できる。
12. 前回基準比20%以上の性能退行を検出し、公開判定へ反映できる。
