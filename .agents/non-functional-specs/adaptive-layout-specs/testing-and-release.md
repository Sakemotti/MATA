# 試験・公開判定仕様

- 文書状態: 確定
- 最終更新日: 2026-08-10
- 親仕様: [画面サイズ・適応レイアウト仕様](README.md)

## 1. 自動試験

### 1.1 サイズクラス

少なくとも次の幅でクラス判定とレイアウトを確認する。

- 320dp
- 599dp、600dp
- 839dp、840dp
- 1199dp、1200dp
- 1599dp、1600dp

高さは次を確認する。

- 320dp
- 479dp、480dp
- 899dp、900dp

- 各境界の直前と境界値で、期待するナビゲーションおよびペイン構成へ切り替わることを確認する。
- 2ペインの利用可能幅736dp境界を、ナビゲーション、Insets、ヒンジ、外側余白を含めて確認する。
- スクリーンショット試験はCompact、Medium、Expanded、Large、Extra-largeの代表値をライト・ダークで実施する。

### 1.2 状態保持

- サイズクラス境界を往復しても、各画面の選択、入力、スクロール、検索、ダイアログを保持する。
- 2ペインと単一ペインの往復で一覧と詳細の戻る階層を保持する。
- 保存、削除、バックアップ、復元、購入中にサイズを変更しても処理を二重実行しない。
- 「元に戻す」の対象と期限をサイズ変更後も保持する。
- Activity再生成とプロセス再生成を分けて試験する。

## 2. 端末・ウィンドウ試験

リリース候補では少なくとも次を確認する。

- 320dp幅の小型スマートフォン
- 標準スマートフォンの縦・横
- 7～8インチ相当タブレットの縦・横
- 10インチ以上のタブレットの縦・横
- ブック型折りたたみ端末の閉状態、開状態、折り途中
- 縦折り端末の閉状態、開状態
- ChromeOSまたはデスクトップウィンドウの最大化、復元、連続リサイズ
- スマートフォンとタブレットの分割画面
- 外部ディスプレイへの移動

- 画面回転ロックの有無にかかわらず、OSから提供された方向で表示できることを確認する。
- ウィンドウを連続的にサイズ変更し、クラッシュ、ちらつき、重複読込、状態消失がないことを確認する。

## 3. Insets・折りたたみ試験

- 3ボタンナビゲーションとジェスチャーナビゲーション
- ステータスバー、ディスプレイカットアウト、パンチホール
- 透明システムバーと各テーマのアイコンコントラスト
- IMEの表示、非表示、キーボード種別変更
- 縦・横の分離ヒンジ、遮蔽ヒンジ、折り目
- システムバーとIMEのアニメーション中

主要な文字、入力、ボタン、FAB、Snackbar、広告をシステム領域またはヒンジが遮らないことを確認する。

## 4. 入力とアクセシビリティ試験

- タッチ、スタイラス、マウス、トラックパッド
- ハードウェアキーボードのみでの全主要フロー
- `Tab`、`Shift+Tab`、`Enter`、`Space`、`Escape`、矢印キー
- ホイールとスクロールバー
- TalkBackとスイッチアクセス
- フォント倍率200%と表示サイズ拡大

カテゴリ作成、TODO作成・編集・完了、日付移動、履歴確認、カテゴリ並べ替え、アーカイブ復元、設定変更までをタッチ以外でも完了できることを確認する。

## 5. 画面別確認

- TODO一覧が全サイズで単一の期限順リストを維持する。
- TODO編集と設定が最大720dpの単一列となる。
- カレンダー、カテゴリ管理、アーカイブ一覧が定義どおりの条件で2ペインへ切り替わる。
- 2ペインでペイン最小幅、間隔、最大幅を満たす。
- カレンダーの日付選択で右ペインだけが更新される。
- 選択対象の削除、復元または検索除外で空詳細へ安全に戻る。
- ダイアログ、ボトムシート、ポップアップが最大幅と安全領域を守る。

## 6. 広告試験

- TODOコンテンツ幅からバナー幅を計算し、ナビゲーション幅を含めない。
- 連続リサイズ中は読み込みを連打せず、幅が300ms安定してから必要な場合だけ再読み込みする。
- 広告の出現、消失、購入直後、読込失敗で空白やTODOの状態消失を発生させない。
- IME、システムナビゲーション、FAB、Snackbarと重ならない。
- 折り目またはヒンジをまたがない。

## 7. 性能基準

- サイズ変更ごとにデータベース全件取得、通知全件再登録、ウィジェット全件更新を開始しない。
- 連続リサイズ中にレイアウト計測、再コンポーズ、広告再読込が無制限に増えない。
- 大量TODO、大量履歴でもサイズ変更後に操作不能となる長時間停止を発生させない。
- Macrobenchmarkまたは同等の計測で代表的なサイズ切り替えと一覧スクロールの退行を検出する。

## 8. 公開条件

次をすべて満たした場合に適応レイアウトを公開可能とする。

1. Android Large Screen App Quality Tier 2の該当要件を満たす。
2. 320dp以上の対応領域で主要操作が欠落しない。
3. すべてのサイズクラス境界でクラッシュ、状態消失、操作不能がない。
4. 縦横方向、分割画面、折りたたみ、ChromeOSで主要フローを完了できる。
5. システム領域、ヒンジ、IME、広告が主要コンテンツを遮らない。
6. タッチ、キーボード、ポインター、TalkBackで主要フローを完了できる。
7. 構成変更中の永続処理が二重実行されず、データと購入状態を破損しない。
8. 適応レイアウトに関するP0・P1試験がすべて合格している。
